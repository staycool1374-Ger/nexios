### #4 — IOMMU DMA protection (capability-gated VT-d tables) (2026-08-30)
- **Learned:** (1) An incremental walk that LINKS freshly allocated table pages immediately must UNWIND them on a later allocation failure — a mid-walk failure otherwise orphans 1-2 linked-but-empty pages that neither the caller's rollback (clear_leaf walks from the root and stops at zeroed entries) nor domain_destroy can ever reach: a permanent PMM leak per failure event (auditor S2). Fix: per-walk `linked_entry/linked_page/nlinked` stack; on failure unlink (parent entry = 0) then free, deepest-first — a failed walk leaves NO state. (2) A struct with raw `uint8_t` fields (arch::PciBdf) times a fixed encoding (device*8+function) reaches 2295 vs. a 256-entry table — the type system gives NO bounds; validate `device<32 && function<8` (bdf_valid) at EVERY indexing site, not just where a syscall feeds it (auditor S2). (3) Full-gate `all` runs are a shared environment: +12 new tests shifted scheduling so the concurrent boot-time elf-loader task (prio 15, "above harness (10)") legitimately won `next_task()` in a test asserting equality to its own prio-10 task — tests running under `all` must assert INVARIANTS (`next->priority >= enqueued`), never exclusive-queue equality; run the class in isolation AND in `all`, and read the test's own diagnostic print (id/prio/name) before touching scheduler code. (4) Hard-coded resource budgets in tests rot silently: idle CRC test bounded 200 iterations (= 800 KiB of .text at 4 KiB/call); kernel .text grew to 831,544 bytes (204 chunks, measured via temporary instrumentation) → derive bounds from runtime link symbols (`kernel::integrity::_text_start/_text_end`, already public in integrity.hpp) + slack instead of a magic constant. (5) `cap::lookup(cspace, h, Frame, 0)` accepts need_rights=0 (passes any rights) — per-slot rights (R→SL read, W→SL write) must be re-read from the EXACT slot the handle addresses (occupied + obj identity + gen match) while the pin is held. (6) The runtime presence flag (`IoMmuManager::probe()`/`force_present()`) must NOT be #ifdef-gated: identical control flow in debug/release keeps the auditor's conditional-semantics check green while tests inject presence. (7) Tooling: `git add -N` (intent-to-add) blocks `git stash -u`, and `stash pop` DROPS the intent-to-add markers — untracked new files then vanish from `git diff HEAD`-generated `audits/pending_patch.diff` (a 239-line patch was silently generated; always verify `grep -c '^diff --git'` matches the expected file count before handing the patch to the auditor). `size build/kernel-debug.elf` under-reports the runtime .text span — use the linker symbols.
- **Adapted:** src/kernel/iommu/vtd.hpp (VT-d entry layouts, single source of truth); src/kernel/iommu/iommu.{hpp,cpp} (IoMmuManager: static bounded domain/root/context tables, identity-IOVA 4-level SL walk with unwind-on-failure, cascade-empty-free, zeroed table pages, bdf_valid guards, leaf SpinLock); src/kernel/cap/iommu.{hpp,cpp} (IoMmuDmaCap, CONFIG_CAP_MAX_IOMMU, revoke destroys domain BEFORE publishing); SYS_IOMMU_MAP=59 / SYS_IOMMU_UNMAP=60 (syscall_handlers_iommu.cpp, MAX_SYSCALL=61); CapType::IoMmuDma=8; class cap_iommu 12 tests; test_expected_counts cap_iommu 12 / all 990; docs/specs/iommu.md (design + phase-2 live-DMAR sketch: ACPI/DMAR discovery, GCMD/IOTLB flush, fault events, kernel-DMA domain, AMD-Vi/SMMU backends); cspace.md §2.6 + configuration.md §1.11 rows. ### #2 — IRQ caps + user-space IRQ delivery (IrqCap) (2026-08-30)
- **Learned:** (1) A capability-wrapped hardware vector needs an OWNER-tagged delivery slot, not just a vector match: a shared (grantable) IrqCap survives its arming task's death, and a drained slot is REUSED for another vector — every path that touches a slot by a stored `reg_idx_` must revalidate `occupied && owner == this && vector == this->vector` under the slot lock, and the ownership-check→arming decision must be ONE atomic critical section (the auditor's iter-2 S1 was exactly the check-then-act TOCTOU between a `slot_belongs_to()` pre-check and a separate `arm()`). `arm(reg_idx, owner, recipient)` folds owner+vector revalidation into the same lock scope; `release_slot_idx(reg_idx, owner)` is atomic (nullptr = ownerless create-failure claim); `claim_slot()` is IrqGuard-serialized. (2) The blocked-wait pattern for a kernel syscall handler is Semaphore::wait(), NOT sys_receive's `sti/hlt/cli` (that is user-only: the iret restores IF; a kernel task that cli()s after hlt keeps IF=0 after wake and is never descheduled — the harness starves). The correct shape: register waiter once under the lock → `dequeue_ready` + `reschedule` → spin on `state == BLOCKED` with `arch::pause()`. A re-registering `for(;;){lock;register;reschedule;}` loop holds the slot lock in a tight spin and livelocks a lower-priority waker (priority inversion). (3) `isr_entry` must gate on `armed && vector == delivered` — consuming a claimed-but-unarmed vector swallows the IRQ line away from any kernel/threaded handler (falls through, single tail EOI). (4) PIC mask restore must be stateful: the boot PIC init unmasks ALL lines, so an unconditional re-mask on release diverges from the pre-arm state — capture `line_was_masked` at arm and restore exactly. (5) Harness spin-waits must re-arm `scheduler_need_resched` + `hlt()` (wait_for_termination_safe pattern), not bare `arch::pause()` — pause-only spins don't reliably dispatch a higher-priority peer under the deferred switch. (6) The `all` class expected-count is the [TCOUNT] added line; IRQ vector 32 (TIMER) must never be user-claimable (the delivery hook sits before the timer ISR path).
- **Adapted:** src/kernel/cap/irq.{hpp,cpp} (IrqCap, CONFIG_CAP_MAX_IRQ, single-owner create, set_slot_owner); src/kernel/irq_delivery.{hpp,cpp} (owner-tagged static delivery table, atomic arm/release_slot_idx, armed-gated isr_entry, drain_task in TCB cleanup, stateful line-mask restore); SYS_IRQ_REGISTER=57 / SYS_IRQ_WAIT=58 (syscall_handlers_irq.cpp, MAX_SYSCALL=59); handle_interrupt_c hook; class cap_irq 12 tests; test_expected_counts cap_irq 12 / all 978. cspace.md §2.6 + configuration.md §1.8 updated. Audit evidence: audits/report-2026-08-30T00-08-05Z.md (APPROVED, 3 iterations). Gates: cap_irq 12/12, cap regressions 0 failures, debug all 963/963 (registered 978), release all 85/85.
- **Style re-surface:** CODING_STYLE §12.5 (ownership checks on EVERY state-changing op — the auditor caught the check-then-act split); §11.6 (atomics/locks all-or-nothing per index — arm/isr_entry/release/drain all on the slot lock); §12.3 (wakers own the wakeup contract — revoke/dispose/drain wake the blocked waiter, never left BLOCKED forever); §11.2 (BLOCKED transitions dequeued, lock released before reschedule); §5.1 (ENSURE only for impossible invariants — exhaustion/validation returns -1); test sanctity (deterministic harness waits over bare spins).

### #1 — Untyped child-split + sub-range carve (2026-08-29)
- **Learned:** (1) The seL4-style exhaustion model for retype: the guard is a "spent" bit, not a "retype once" bit — a sub-range carve transfers [0,carve) to the target and [carve,size) to a NEW child Untyped, so a region splits repeatedly. Single-owner-per-frame requires enumerating EVERY failure path after the guard flips: FrameCap::create null (rollback claim), child-creation null (STRETCH the never-installed FrameCap to the whole region and release — the region returns to PMM exactly once, parent stays spent), target-install fail (release fc + child = paired partial owners cover the region), child-install fail (cspace->remove(target) then fc->release() THEN child->release() — the creator ref is separate from the slot ref; forgetting fc->release() leaks the MemPool block AND the carved pages, caught by the auditor as S2). (2) A child installed with the caller's rights verbatim can become non-retypable (retype requires CAP_RIGHT_WRITE on the Untyped slot): install children with `rights | CAP_RIGHT_WRITE` — the caller already held WRITE over the parent region, so this grants no new authority. (3) Non-destructive slot-capacity pre-check (occupied_count + n_slots <= CONFIG_CSLOT_COUNT) before claim keeps the parent intact on table-full; without the rollback fix it also makes the leak path reachable. (4) find_slot_of(type) returns the FIRST matching slot — after a two-level split the spent child is still installed, so a grandchild scan must exclude BOTH spent parents. (5) SYS_CAP_RETYPE on the caller root CNode: current_cspace() + 4-arg marshalling; garbage target_type is rejected by the `!= retype_target` check.
- **Adapted:** src/kernel/cap/untyped.{hpp,cpp} (create_subrange, exhaustion-model retype, shared g_live_untypeds bound counting children); cap.hpp retype doc; SYS_CAP_RETYPE=56 + syscall_handlers_cap.cpp; class cap_untyped 9→18 tests; test_expected_counts cap_untyped 18 / all 966; docs/specs/cspace.md §2.8 (exhaustion model, child atomicity, stretch fail-closed, counts). ### #3 — MMIO caps + fine-grained I/O delegation (2026-08-25)
- **Learned:** (1) The single most dangerous kernel pattern for ANY new per-task field: `TaskControlBlock::create/create_user/clone` AND the ELF loader (`finalize_loaded_task`) each do `memset(tcb, 0, sizeof(TaskControlBlock))` and NEVER run the C++ constructor — a new field whose ctor init-list sets a non-zero sentinel is silently 0 in every real TCB. This made `iopb_slot_`=0 (not IOPB_SLOT_NONE), so every user task loaded the never-claimed all-zeros pool slot into the TSS I/O bitmap on dispatch → ALL ports allowed (default-deny violated = privilege escalation). Fix = set the sentinel explicitly after every memset site (4 sites) AND defense-in-depth: never trust a slot value — the loaded TSS bitmap must always be exactly a CLAIMED slot (`g_iopb_claimed & (1<<slot)`), and `iopb_claim` self-heals stale non-NONE slots. (2) The TSS I/O permission bitmap must live INSIDE the TSS segment (descriptor limit = sizeof(TSSBlock)-1, iopb_offset = offsetof(iopb)); an all-zeros bitmap means all ports allowed — default-deny is all-1s + a 0xFF terminator byte. (3) A user task that grants itself ports needs the bitmap applied immediately (not on its next context switch) — the syscall handler must call iopb_switch_to after grant. (4) Ring-3 #GP on denied ports is untestable from the ring-0 harness — assert bitmap state + TSS layout + owner bookkeeping instead. (5) The release build's `-fanalyzer -Werror` flags GCC 14 false positives (array-bound under-read on macro-sized arrays, null-argument on lambdas) — the Makefile already downgrades a list of analyzer warnings; adding the out-of-bounds one was required. (6) `all` class PLANNED vs EXECUTED differ (TF_BENCH/TF_USER filtering): registered=957, executed=942 — update test_expected_counts from the `[TCOUNT] class=all added=` line, not from the executed summary.
- **Adapted:** src/kernel/cap/mmio.{hpp,cpp} (MmioCap, CONFIG_CAP_MAX_MMIO); VMM::map_mmio_from_cap/unmap_mmio_from_cap; SYS_IOPORT_GRANT=55 + syscall_handlers_mmio.cpp; arch::iopb_* + TSSBlock (x86_64 hal/gdt + iopb); TCB memset sentinel fix (task.cpp x3 + elf.cpp); claimed-slot defense in iopb_claim/switch_to/grant_range/port_allowed; Makefile analyzer exception; class cap_mmio (10 tests). cspace.md §2.6 + configuration.md §1.8 updated. Audit reports: report-2026-08-25T16-28-01Z.md + report-2026-08-25T17-01-35Z.md (both APPROVED). Gates: cap_mmio 10/10, debug all 942/942, release all 85/85, selftest 133/133.
- **Style re-surface:** CODING_STYLE §4 (no dynamic allocation on RT paths → static iopb pool); default-deny as the baseline invariant (like the aarch64 PAN work: never trust "off by default" unless it is mechanically enforced); fail-closed pool exhaustion (never panic — return -1); test sanctity (walk/state-level assertions when the fault behavior is not reachable from the harness); the memset-not-ctor TCB pattern must be documented wherever a TCB field with a non-zero default is added.

### #5 — MP-4.4: aarch64 PAN/PXN enablement (2026-08-25)
- **Learned:** (1) QEMU `-cpu cortex-a72` reports ID_AA64MMFR1_EL1.PAN == 0, so PAN cannot be runtime-enabled in the current test profile — the enable path must be a runtime-gated feature (g_pan_supported + degraded no-op stac/clac/read_rflags), never a compile-time assumption, or the aarch64 build silently ships stubs on the only platform we can boot. (2) ROADMAP's "PAN (bit 22 of SCTLR_EL1)" conflates two different bits: SCTLR_EL1.PAN is bit 23; PSTATE.PAN is bit 22 of the PAN sysreg (S3_0_C4_C2_4) toggled via `msr pan`/raw sysreg. (3) The aarch64 page_table_impl wrote an L3 leaf with bits[1:0]=0b01 (reserved at L3 — page descriptors must be 0b11, DESC_TABLE; only L2 blocks use 0b01) — a latent runtime boot blocker only reachable once the aarch64 boot path actually maps 4K pages. (4) stac/clac can be mirrored without changing consumers by normalizing read_rflags to the x86 bit-18 "override active" contract (bit 18 set ⟺ PSTATE.PAN==0); exception entry/ERET restore PSTATE so stac windows survive IRQs. (5) aarch64 DOES boot in QEMU today (reaches kernel init) but PMM OOMs at meminit — the DTB memory regions are never seeded into PMM (x86 path consumes the multiboot2 map; filed as #100 under #28).
- **Adapted:** SCTLR_EL1.PAN (bit 23) + ID_AA64MMFR1_EL1.PAN detection in arch::pan_init(); CONFIG_PAN; PAN-sysreg stac/clac/read_rflags in aarch64 io_impl.hpp; PXN(53)/UXN(54) closure (attr_from_flags USER PXN = SMEP parity, VMM aarch64 map paths, block-split base_flags); L3 DESC_TABLE fix; 5 new arch_aarch64 tests + map_leaf TEST_VA moved off a boot 2MB block. Audit: audits/report-2026-08-25T15-05-22Z.md (APPROVED). x86_64 arch_cross 21/21 regression; aarch64 runtime test execution deferred to #28/#100.
- **Style re-surface:** CODING_STYLE arch-guard placement (all aarch64 edits inside CONFIG_ARCH_AARCH64, x86_64 path byte-identical); test sanctity (walk/register-level tests only — no deref of a mapped USER page when no recover_ip fault path exists); ENSURE only for impossible invariants (the aarch64 boot OOM is a reachable precondition failure, tracked as a bug not an assert).

### #6 — Implement all pending audits/refactorings under audits/ (2026-08-25)
- **Learned:** (1) The single most reusable kernel-blocking pattern is "release the primitive lock BEFORE reschedule/dequeue_ready" — holding a spinlock across the INV-4 deferred switch deadlocks the ISR-side waker; every blocking path (semaphore/eventgroup/queue/mutex) must mirror Queue/Notify: guard scoped to waiter-insert, then dequeue_ready + reschedule outside, with an interrupts-disabled rollback (remove waiter, RUNNING, enqueue_ready). (2) Generation-tagging bare TCB pointers (waiter_, last_sender_/last_receiver_) defeats ABA from recycled TCBs — check REAPED state AND captured generation, but allow TERMINATED zombies (still allocated) so PIP boosts on recently-terminated holders keep working. (3) The custom Logger reads ALL integers as uint64_t and previously mishandled `%llu` (skipped only one 'l'), leaving the va_arg list misaligned for a following `%s` → crash only on the H2-flake diagnostic branch. (4) The LSTAR/sysret path was a guaranteed-panic landmine (MSR_KERNEL_GS_BASE never written → swapgs left GS base 0 → mov [gs:0],rsp #PF on phys 0); int $0x80 is the only safe syscall entry. (5) Priority-inheritance restore must use strict `>` (not `>=`) or the holder_priority_ latch never clears → permanent priority inflation. (6) Endpoint dispose must drain blocked senders itself — the embedded MessageQueue dtor never runs under MemPool::free. (7) `%u` with a 32-bit cast on a 64-bit id in the custom logger leaves garbage high bits.
- **Adapted:** 8 SIL-3-approved commits (P1–P8): semaphore/eventgroup lock-scope + dequeue_ready; notify/queue generation-tags + PIP re-bucketing via move_priority; TCB::destroy() pool-aware helper; scheduler alloc_id table-full contract + atomic next_task_id_ + validate_iret_frame helper + task_stack_ptr inline; BufferPool map owner/VA/TLB-flush; Endpoint dispose drain + disposed_ re-check; AHCI/virtio serialization + GHC_IE removal; LSTAR removal (syscall.cpp no-op + mk/rules.mk unassembled + test_idt companion); Mutex H-4 retry; TaskQueue orphan-drop; SPSC atomics. Each phase has an immutable audit report in audits/. Full debug `all` 932/932, release selftest 85/85.
- **Style re-surface:** CODING_STYLE §5 (ENSURE only for impossible invariants; reachable exhaustion → error/retry); §4 (no new/delete on RT paths → destroy() helper); no spinlock across a context switch; IrqGuard only for boot/panic/test-isolation (ROADMAP guardrails); test sanctity (doc-block + implementation updated together when a fix changes expected behavior).

### #99 — Multi-arch compile-clean: aarch64 + riscv64 link green (2026-08-25)
- **Learned:** (1) Cross-arch builds with a shared `build/` require the arch-switch clean at PARSE TIME, before `-include $(DEPFILES)` — a mid-build clean (rule prerequisite) is too late because make commits to "object up to date" from the previous arch's `.d` files and never rebuilds it (caused `cannot find build/initrd/initrd.o`). (2) The old `gen_test_registry.py` had a legacy truncation bug: its `#else` depth arithmetic left `disabled_depth` elevated, silently dropping the tail of files (test_stack_alloc.cpp lost 5 real tests from the dormant `generated_tests[]`). (3) AArch64 `ADR_PREL_PG_HI21` can't reach low-VMA symbols from higher-half `.text`; higher-half boot-stack symbols must be linker absolute symbols (`HHDM + low_vma`). (4) riscv64 inline asm uses `mv` (no `mov`); aarch64 uses `mov %0, sp`.
- **Adapted:** Makefile parse-time arch-stamp check + per-arch `mk/cpp-rules.$(ARCH).gen.mk`; `tools/gen_test_registry.py` arch-aware stripping (SCAN/DROP/ARCH mode stack); `linker/linker_aarch64.ld` `_stack_start`/`_stack_end` absolute symbols; scheduler.cpp/task.cpp `CONFIG_ARCH_X86_64` guards.
- **Style re-surface:** CODING_STYLE preprocessor-guard placement (whole contiguous statement groups, x86_64 path byte-identical); minimal-diff discipline; Werror-clean.
