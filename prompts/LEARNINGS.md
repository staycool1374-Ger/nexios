### #7 — User-Space IRQ Delivery System: NOTIFY-mode capability-backed IPC bridge (2026-09-01)
- **Learned:** (1) The IRQ→IPC notification bridge (issue #7) is a DELTA on the closed #2 delivery table, not new syscalls: reuse `IrqDelivery` slots and add a per-slot `IrqDeliveryMode{WAIT,NOTIFY}` bound atomically at arm() under the slot lock. The mode must be read/written ONLY inside that lock scope (same check-then-act TOCTOU discipline as #2's owner revalidation). (2) Auditor S2: a user-controlled uint64 syscall arg must be validated RAW (`arg1 != 0 && arg1 != 1`) BEFORE the narrowing `static_cast<IrqDeliveryMode>` — otherwise 0x101→NOTIFY and 0x100→WAIT wrap into valid modes and defeat the "unknown modes fail closed" contract; probe the wrapping value (0x101) in a test, not just an obviously-invalid 2/0xFF. (3) `Notify::wait()` is NOT a spinning block like sys_irq_wait: it sets BLOCKED + arms a deferred reschedule and RETURNS immediately — the switch only applies on the next timer tick. A test worker that assumes wait() blocks runs to termination before the harness can wake it (test hung; harness gate `task_blocked` never observed BLOCKED). Fix: mirror sys_irq_wait's explicit `while (state == BLOCKED) arch::pause()` spin AFTER wait() returns, then RE-READ the delivered value via `notify.try_wait()` (wait() may have returned a stale 0 when the ISR delivered while descheduled). (4) In release_slot_idx/drain_task the wake target fields (`recipient`/`recipient_gen`) must be captured BEFORE clearing them — clearing first silently nulls the notify target and leaves the driver BLOCKED forever (the hang was a wake-ordering bug, not a lock issue). (5) drain_task ordering trap: `TaskControlBlock::cleanup()` destroys `~Notify` (task.cpp:1857) BEFORE `IrqDelivery::drain_task` (task.cpp:1870) — draining a NOTIFY slot whose recipient is the dying task must NEVER call notify() on the destroyed object (UAF); the wakers-own-wakeup contract does not apply to an already-TERMINATED task. (6) The revoked sentinel for NOTIFY mode is 0 (`sync::NOTIFY_INVALID`): it wakes a BLOCKED waiter but is invisible to polling `try_wait()` (which only consumes non-zero values) — document this asymmetry in the spec so polling drivers don't rely on observing revocation. (7) EventGroup mode was DEFERRED (scope decision posted on the issue): EventGroup has no value/error channel, its multi-waiter model mismatches the single-recipient slot, and the revoke-wake contract would need a documented bit protocol.

### #103 — aarch64 deep_copy_user_pages invalid L3 table descriptors (2026-09-01)
- **Learned:** (1) On aarch64 stage-1 the descriptor-encoding rules differ by LEVEL: block descriptors (L1/L2) are bits[1:0]=01, PAGE descriptors (L3) are bits[1:0]=11, and TABLE descriptors (L0/L1/L2 next-level pointers) are ALSO bits[1:0]=11 — a table pointer built as `PAGE_PRESENT|PAGE_WRITE|PAGE_USER` (x86 idiom) collapses to bits[1:0]=01 on aarch64 (PAGE_WRITE=0, PAGE_USER=1<<6) and is a reserved/invalid encoding: every MMU walk of the space translation-faults. `#if CONFIG_ARCH_AARCH64` guards that emit `PAGE_PRESENT|PAGE_TABLE` at table-pointer sites are mandatory; the x86 arm stays byte-identical. (2) AF (bit 10) and AttrIndx (bits[4:2]) are RES0/IGNORED in stage-1 TABLE descriptors — the minimal table-pointer form is `PRESENT|TABLE`; the L3 LEAF carries AF/AttrIndx (set by map_page / inherited by deep-copy verbatim flags). Mirror the e24b1415 table sites, not the leaf sites. (3) When a mid-test `JARVIS_ASSERT` aborts, teardown does NOT run → the harness reports `LEAK: PMM +N`; that's a symptom (assertion too late/loose), not a real leak — put teardown-correctness checks in a state that completes. (4) Leaf-frame extraction must use the arch 48-bit frame mask (`0x0000FFFFFFFFF000`), never `~0xFFF` — user leaves carry UXN(54)/PXN(53) and `~0xFFF` leaks them into the "phys" (same class as the #100 DESC_PHYS_MASK defect). (5) Userspace probes with arch-specific inline asm (ud2/divq) compiled via the `userspace/%.c.elf` pattern rule for EVERY arch silently break the aarch64/riscv64 build — guard probe bodies with `#if defined(__x86_64__)` (inert elsewhere; the loading tests are x86-guarded). The #91 x86-only probes went unnoticed because #91 never built a cross-arch target; cross-arch builds are the regression net. (6) An ISSUE-level "smoke test when runtime resumes" requirement can outscope the deterministic fix gate: the EL0 fork smoke test depends on unexercised aarch64 scheduler/process infrastructure — defer to a follow-up issue (#104) rather than balloon the gate, and make the smoke test assert a POSITIVE child-execution marker (a translation-faulted child also terminates).
- **Adapted:** src/kernel/memory/vmm.cpp deep_copy_user_pages (3 arch-guarded table-descriptor sites → `PAGE_PRESENT|PAGE_TABLE`); src/kernel/arch/aarch64/test_aarch64.cpp `aarch64_deep_copy_user_descriptors_valid` (arch_aarch64 22→23, HHDM-walk descriptor-encoding gate, 48-bit frame mask, symmetric free_user_pages/free_page); userspace/ud-probe.c + de-probe.c (`__x86_64__` guards); test_expected_counts.hpp arch_aarch64 0,23; issue #104 follow-up filed. Audit evidence: audits/report-2026-09-01T06-34-48Z.md (APPROVED, 0 findings). Gates: aarch64 arch_aarch64 23/23, arch_cross 16/16; x86_64 exc_table 3/3, process_pml4_clone 10/10, debug all 981/981, release all 85/85. Commit `49462ae9` (closes #103).

### #91 — ISR_NOERR misclassification: #VE(21)/#HV(28) push error codes (2026-08-31)
- **Learned:** (1) Per-vector error-code classification is a real correctness hazard, not style: on modern CPUs vec 21 (#VE Intel VMX / #CP AMD CET) and 28 (#HV) DO push an error code. Declared ISR_NOERR, the CPU-pushed error code is consumed as the first GPR (RAX) by isr_common, so the C dispatcher reads garbage, and iretq pops a misaligned frame ⇒ triple-fault-class on any host that raises them (latent on QEMU without nested virt). A macro-level `%assign` frame audit pins BOTH stub classes to the same 16-byte frame (NOERR = synthetic 0 + vec; ERR = 8-byte CPU code + vec) and makes any drift a build failure — but it can NOT catch a silent classification swap (identical frame sizes), so the exported `__isr_vectors_err_mask` + a mask-equality test is the regression gate, and it must live in the `all` gate (auditor S3). (2) A reserved-vector fail-stop policy (15, 22-26, 29, 31 → panic, not user-mode SIGSYS) is a deliberate fault-isolation→fail-stop shift the auditor must flag; it is safe here because no normal hardware raises those vectors, and the branch sits after the `g_user_access_recover_ip` redirect so safe_copy recovery still wins inside the copy window. (3) Weak-hook test seams: a `__attribute__((weak))` no-op production hook overridden by a strong test symbol (the stack_overflow_hook pattern) gives a deterministic dispatch probe with EXACT production parity when unarmed; the armed-latch must be confined to `arch::IrqGuard` scopes so a real timer IRQ can never be swallowed (residual NMI hole is theoretical + self-detecting). (4) Compiler folding defeats fault-probes: `1UL / runtime_value` is rewritten by GCC into a compare (`1/x == (x==1)`) with NO division instruction — a real `#DE`/`#UD` probe must use inline asm (`ud2`; `divq %rcx` with zero divisor). (5) Count-table drift is silently warn-only: memory_pmm 5→8 (issue #100) left `all`=990 stale while registered was 993; safe/selftest 132→133 predated too. `[TCOUNT] MISMATCH` must be treated as a defect (fix the row), never ignored — and a new test class needs the `register_all_tests()` line (not just the g_test_classes entry) to be protected by the `all` gate. (6) `initrd::find` normalizes `./` on both sides, so a `name+2` "strip ./" fallback is dead buggy code — the auditor flagged it.

### #100 — aarch64 runtime bring-up: daemon-ready handshake + arch_aarch64 22/22 (2026-08-31)
- **Learned:** (1) An architecture-specific syscall-ABI mismatch is invisible in a boot that "works" — every aarch64 user syscall dispatched on saved x0 (user arg0) instead of x8 (Linux-AArch64 number), so getpid→SYS_YIELD, write→SYS_SEND, ipc_send→wrong dest: vfsd/iocd "executed fault-free" yet the ready-IPC never reached PID 1. A short ABI trace at syscall_handler entry proved it in one run. Anchor the ABI in a comment at the single source of truth (src/libc/syscall.h) so entry stubs and libc can't drift. (2) `switch_away_from_terminating` used x86-only iret-frame validation (CS==0x8/0x1B, SS==0x23) with NO aarch64 branch — it DEQUEUED the candidate via next_task() then discarded it on the failed validation and fell back to idle, leaving init READY but inrq=0 (stranded, never dispatched). Any second site that validates a task frame must be arch-gated like the dispatch guard. (3) aarch64 kernel-task frames built with SPSR=0x3C5 (ALL mask bits set) are UN-PREEMPTIBLE: a voluntary reschedule() (elf-loader's IDLE block) arms a deferred switch that only the NEXT timer IRQ applies — with IRQs masked it spins forever, starving the harness. x86 kernel tasks resume with IF=1; aarch64 must resume with I=0 (SPSR 0x345). Symptom signature: task READY + dequeued + spins in a block loop while the higher-priority peer never yields. (4) Page-table pages MUST be dereferenced through the HHDM alias, not raw phys VAs: raw phys resolves through whatever TTBR0 is active (a per-task private PML4 clone), silently reading the wrong memory. (5) `& ~0xFFF` is NOT a phys mask on aarch64: leaf descriptors carry UXN(54)/PXN(53) above the address bits — use a 48-bit `DESC_PHYS_MASK`; free_page() of an unmasked address silently no-ops (leak). (6) QEMU virt aarch64 PCIe ECAM is 0x3f000000 (0x30000000 is the riscv64 base and sits INSIDE the PCI MMIO window); 0x100000000 is unmapped. A wrong MMIO base can manifest as silent external-abort-skipped reads ("32 devices" garbage) or a boot-time fault spiral into address-0 execution (default_exception silently skips elr+4). (7) boot.S page tables at the RAM base (0x40000000) clobber QEMU's DTB; relocate them above the blob. (8) The aarch64 RTC must read the PL031 wall clock, not CNTPCT (seconds-since-boot). (9) LTO eliminated a dead aarch64-only function in the DEBUG x86 link but not RELEASE (assembler chokes on `mrs elr_el1`) — arch-gate aarch64-only functions explicitly, don't rely on LTO dead-code elimination. (10) The build system's parse-time arch-stamp does NOT fire for positional-arch `make execute-test <arch> ...` (ARCH is evaluated in the rule body) — switching arches without `rm -rf build` mixes objects and leaks `-mabi=lp64` into the x86 link; clean manually between arches.

### #4 — IOMMU DMA protection (capability-gated VT-d tables) (2026-08-30)
- **Learned:** (1) An incremental walk that LINKS freshly allocated table pages immediately must UNWIND them on a later allocation failure — a mid-walk failure otherwise orphans 1-2 linked-but-empty pages that neither the caller's rollback (clear_leaf walks from the root and stops at zeroed entries) nor domain_destroy can ever reach: a permanent PMM leak per failure event (auditor S2). Fix: per-walk `linked_entry/linked_page/nlinked` stack; on failure unlink (parent entry = 0) then free, deepest-first — a failed walk leaves NO state. (2) A struct with raw `uint8_t` fields (arch::PciBdf) times a fixed encoding (device*8+function) reaches 2295 vs. a 256-entry table — the type system gives NO bounds; validate `device<32 && function<8` (bdf_valid) at EVERY indexing site, not just where a syscall feeds it (auditor S2). ### #2 — IRQ caps + user-space IRQ delivery (IrqCap) (2026-08-30)
- **Learned:** (1) A capability-wrapped hardware vector needs an OWNER-tagged delivery slot, not just a vector match: a shared (grantable) IrqCap survives its arming task's death, and a drained slot is REUSED for another vector — every path that touches a slot by a stored `reg_idx_` must revalidate `occupied && owner == this && vector == this->vector` under the slot lock, and the ownership-check→arming decision must be ONE atomic critical section (the auditor's iter-2 S1 was exactly the check-then-act TOCTOU between a `slot_belongs_to()` pre-check and a separate `arm()`). `arm(reg_idx, owner, recipient)` folds owner+vector revalidation into the same lock scope; `release_slot_idx(reg_idx, owner)` is atomic (nullptr = ownerless create-failure claim); `claim_slot()` is IrqGuard-serialized. (2) The blocked-wait pattern for a kernel syscall handler is Semaphore::wait(), NOT sys_receive's `sti/hlt/cli` (that is user-only: the iret restores IF; a kernel task that cli()s after hlt keeps IF=0 after wake and is never descheduled — the harness starves). The correct shape: register waiter once under the lock → `dequeue_ready` + `reschedule` → spin on `state == BLOCKED` with `arch::pause()`. A re-registering `for(;;){lock;register;reschedule;}` loop holds the slot lock in a tight spin and livelocks a lower-priority waker (priority inversion). (3) `isr_entry` must gate on `armed && vector == delivered` — consuming a claimed-but-unarmed vector swallows the IRQ line away from any kernel/threaded handler (falls through, single tail EOI). (4) PIC mask restore must be stateful: the boot PIC init unmasks ALL lines, so an unconditional re-mask on release diverges from the pre-arm state — capture `line_was_masked` at arm and restore exactly. (5) Harness spin-waits must re-arm `scheduler_need_resched` + `hlt()` (wait_for_termination_safe pattern), not bare `arch::pause()` — pause-only spins don't reliably dispatch a higher-priority peer under the deferred switch. (6) The `all` class expected-count is the [TCOUNT] added line; IRQ vector 32 (TIMER) must never be user-claimable (the delivery hook sits before the timer ISR path).

### #1 — Untyped child-split + sub-range carve (2026-08-29)
- **Learned:** (1) The seL4-style exhaustion model for retype: the guard is a "spent" bit, not a "retype once" bit — a sub-range carve transfers [0,carve) to the target and [carve,size) to a NEW child Untyped, so a region splits repeatedly. Single-owner-per-frame requires enumerating EVERY failure path after the guard flips: FrameCap::create null (rollback claim), child-creation null (STRETCH the never-installed FrameCap to the whole region and release — the region returns to PMM exactly once, parent stays spent), target-install fail (release fc + child = paired partial owners cover the region), child-install fail (cspace->remove(target) then fc->release() THEN child->release() — the creator ref is separate from the slot ref; forgetting fc->release() leaks the MemPool block AND the carved pages, caught by the auditor as S2). (2) A child installed with the caller's rights verbatim can become non-retypable (retype requires CAP_RIGHT_WRITE on the Untyped slot): install children with `rights | CAP_RIGHT_WRITE` — the caller already held WRITE over the parent region, so this grants no new authority. (3) Non-destructive slot-capacity pre-check (occupied_count + n_slots <= CONFIG_CSLOT_COUNT) before claim keeps the parent intact on table-full; without the rollback fix it also makes the leak path reachable. (4) find_slot_of(type) returns the FIRST matching slot — after a two-level split the spent child is still installed, so a grandchild scan must exclude BOTH spent parents. (5) SYS_CAP_RETYPE on the caller root CNode: current_cspace() + 4-arg marshalling; garbage target_type is rejected by the `!= retype_target` check.

### #3 — MMIO caps + fine-grained I/O delegation (2026-08-25)
- **Learned:** (1) The single most dangerous kernel pattern for ANY new per-task field: `TaskControlBlock::create/create_user/clone` AND the ELF loader (`finalize_loaded_task`) each do `memset(tcb, 0, sizeof(TaskControlBlock))` and NEVER run the C++ constructor — a new field whose ctor init-list sets a non-zero sentinel is silently 0 in every real TCB. This made `iopb_slot_`=0 (not IOPB_SLOT_NONE), so every user task loaded the never-claimed all-zeros pool slot into the TSS I/O bitmap on dispatch → ALL ports allowed (default-deny violated = privilege escalation). Fix = set the sentinel explicitly after every memset site (4 sites) AND defense-in-depth: never trust a slot value — the loaded TSS bitmap must always be exactly a CLAIMED slot (`g_iopb_claimed & (1<<slot)`), and `iopb_claim` self-heals stale non-NONE slots. (2) The TSS I/O permission bitmap must live INSIDE the TSS segment (descriptor limit = sizeof(TSSBlock)-1, iopb_offset = offsetof(iopb)); an all-zeros bitmap means all ports allowed — default-deny is all-1s + a 0xFF terminator byte. (4) Ring-3 #GP on denied ports is untestable from the ring-0 harness — assert bitmap state + TSS layout + owner bookkeeping instead.
