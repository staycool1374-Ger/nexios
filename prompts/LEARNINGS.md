### #129 — Coverage closure: kernel/profiling 36.4% → 100% (sampling profiler API) (2026-09-07)
- **Learned:** (1) The sampling profiler is NOT coverage instrumentation and NOT debug-only — `Sampler::init()/set_sample_rate(10)/set_enabled(true)` run unconditionally at boot (`kernel.cpp:933-935`, no `CONFIG_DEBUG` gate) and `record_sample()` is called from the **timer ISR** (`hal/timer.cpp:100`). It is production code on the interrupt path in every build; coverage is `src/kernel/gcov/` + `-finstrument-functions` (#123), a different subsystem. (2) `record_sample()` is driven concurrently by the timer ISR, so any measurement of it must run inside an `arch::IrqGuard` (scheduler frozen) AND start from `clear()` — `clear()` resets `sample_seq`, which is what makes the rate gate reproducible. Without the guard the ISR contributes unknown samples. (3) The rate gate is `seq % rate != 0` over an internal monotonic counter, deliberately NOT over `arch::Timer::ticks()` (the harness rewinds ticks, which starved the sampler — a boot tick of 0 produced the only sample ever taken). So with rate N exactly every N-th call is kept: rate 4 over 8 calls = 2 samples, rate 1 = 8. (4) The ring is a 4096-entry power-of-two array with a free-running head: wrapping drops OLD SAMPLES but `sample_count` is a running total and is NOT clamped — recording 4106 samples yields `get_sample_count() == 4106`, not 4096. Only `dump_to_serial()` clamps its output count. (5) `add_function`/`register_from_symbol_table` have no boot callers, so `func_count` starts at 0 and the first registered range is index 0 — symbol indices are deterministic in tests. Ranges are half-open `[start,end)`. Malformed records are rejected by `start != 0 && end_addr > start`. (6) `dump_to_serial()` writes to the debugcon port 0xE9, so it is neither observable via `Terminal::capture_*` nor via the klog ring — assert only that it is non-destructive (sample count unchanged). (7) Every test must restore the boot state (enabled, rate 10, cleared) BEFORE its first assertion, since `JARVIS_ASSERT` returns on failure and would otherwise leave the profiler disabled for the rest of the suite.
- **Adapted:** src/kernel/test/test_profiler_sampler.cpp (class `profiler_sampler`, 6); test_registry.cpp (class entry + register_all_tests()); test_expected_counts.hpp (profiler_sampler 6). Measured: kernel/profiling 11/11 = 100%.

### #128 — Coverage closure: kernel/debug 8.3% → 83.3% (post-mortem dump smoke) (2026-09-07)
- **Learned:** (1) **The test-time logger channel is not the UART.** `Logger::putchar/puts` route to QEMU debugcon (`arch::QemuDebugcon`) whenever `Scheduler::is_test_active()` — so `Terminal::capture_begin/end()` sees nothing AND `arch::Serial::write_count()` stays frozen (my first attempt measured it; all four tests failed with a delta of 0). ### #125 — Coverage closure: services 40.3% → 83.7% (shell command surface, terminal, program registry) (2026-09-07)
- **Learned:** (1) `service::Terminal::capture_begin(buf,size)` / `capture_end()` is the ONLY sane observation channel for shell commands — the serial-loopback trick used by the older shell tests is limited by the 16-byte UART RX FIFO and cannot see a whole command's output. `Shell::execute()` + capture gives exact, deterministic text assertions. (2) `putchar()` emits to serial **and** to the capture buffer BEFORE the `fb_enabled_` gate — so disabling the framebuffer does NOT silence capture (a test can assert that the serial channel is independent of rendering).
