## INVARIANTS & CONCURRENCY BOUNDARIES
- **New predicate R4' (replaces rule 4 at all three service points).** Let `E = Scheduler::scheduler_lock_held() || scheduler_lock_depth_own() != 0` read **at the instant of the increment**. A covered instant accrues iff (a) the service point is on the latch's CPU, (b) `now != latch.last_cover_tick` (at most one increment per distinct tick value), (c) `E`. If (a),(b) hold and (c) fails: `covered_ticks := 0`, `s_lockpark_free_nodeliver++`, one `SCHED+24` WARN per latch lifetime, **latch retained** (no clear here — clear precedence stays stale→woke→hook, unchanged).
- **E read+accrue atomicity (S2, load-bearing: E is the sole gate of a kernel FATAL).** Guard discipline is mark-AFTER-take / unmark-BEFORE-release (scheduler_lock_guard.hpp:71-99), so E is true throughout both transitions: a take between the word-load and the accrue only extends a true interval; a release is unmarked before the word clears, so only a *post-clear remote release* landing inside the load-accrue window miscounts (over-count, one instant). A remote take landing between the read and a reset drops one held instant (under-count, one instant of tripwire delay). Local (same-CPU, IF=0 tick) transitions cannot interleave at all. Panic needs 8 *consecutive same-direction* races inside nanosecond windows - the bound is robust to isolated single-instant errors in either direction. Applies identically at pre/miss/post sites.
- **R5' unchanged:** `covered_ticks >= kLockParkCoveredLimit (8)` ⇒ SCHED+17 + §4.9 dump + panic. Post-fix reading: *8 distinct ticks with the scheduler lock observed held/owned while a latched runner stayed undelivered.*
- The `:165`-fail observation is **not** evidence by itself (r6 S3 shape); `E` is re-read at the increment — the documented task-context reentrancy still counts (own depth ≠ 0 ⇒ E true), so that shape stays counted and stays honest.
- `last_cover_tick` is carried through `LockParkWatch` like `covered_ticks`/`warned`, cleared by `s582_latch_clear`, preserved by a same-`{id,generation}` re-arm. Per-CPU single-writer (tick ISR + task-context `on_tick` reentrancy on the same CPU) → `__atomic_store_n/load_n` RELAXED, matching the existing `covered_ticks` discipline.
- **Bounded/IRQ/lock discipline of the added checks (tick path):** +1 atomic word load (`scheduler_lock_held()` = `is_locked_for_debug()` atomic read, scheduler.hpp:311-313), +1 per-CPU scalar load (`scheduler_lock_depth_own()`, scheduler_lock_guard.hpp:53-55), ≤1 store. No lock take, no allocation, no task-list walk, no logging on the steady path, no IRQ state change, no ready-queue/task-state mutation. Runs inside the timer ISR (IF=0) exactly as today.
- **Fence properties from `audits/design-review-582-r6.md` all preserved:** (1) rules 1/2 silent-clear precedence first — unchanged; (2) class never decision-read — unchanged (evidence is runtime lock state; `LockParkClass` uses stay arming-writers/struct/getter/formatter only); (3) monotonic clock across re-arm — AMENDED (explicit, not unchanged): R4' adds a free-observation reset path alongside the clear path. No r5 rearm-livelock: a true wedge holds the word continuously ⇒ no !E ⇒ fires; free gaps mean dispatch was possible ⇒ reset is honest; (4) single FailClosed predicate (covered>=8) — unchanged; (5) miss-path double-read discipline — unchanged; (6) dump ≤10 + ≤8 DEBUG lines — unchanged; (7) hook five-term discriminator + "never reads the class" — unchanged.
- **No-weakening contract:** must still fire = `E` true on 8 distinct ticks (SelfLock latch with the word held; own-depth reentrancy cover; cross-CPU chained holders, r6 :250-251). Must stop = the witness (ExternalDenial latch + legal wheel/IPC/harness block with a free lock) and the miss+post double increment. Chained holders with free gaps (scheduler.md:250-251): fires iff gaps are absent across the 8 ticks; resets iff a gap proved dispatch possible.

## SIL 3 / SAFETY RISKS
- [S1] **Deliberate weakening: free-lock non-delivery stops panicking** — a genuinely wedged BLOCKED-never-dispatched runner loses its FATAL. *Mitigation:* the latch is retained (hook/wake/stale clears still own its lifecycle), the shape stays visible via `s_lockpark_free_nodeliver` + one-shot SCHED+24 WARN, and `scheduler_lock_`-held escalation is bit-identical. The alternative (keep panicking to "stay fail-closed") is rejected: it is the false positive itself, and #608's charter is detection, not silence — the record must state the trade explicitly on the issue and in the audit report.
- [S1] **Wrong evidence read `E` would restore the false positive or mask a true one.** `E` must be read inside the service core, after RMS's adopted guard has destructed (scheduler_tick.cpp:1139), never from a pre-RMS snapshot. If recon (0.3) shows `E` true at a legal post instant, the fallback is to pass the pre-time `deliverable` bit into `LockParkWatch` and require "RMS did not run (miss)" as the only post-time evidence — do not ship a partially-correct `E`.
- [S2] **Per-CPU single-writer assumption** on `last_cover_tick` (tick ISR + task-context `on_tick` reentrancy on the same CPU) — use `__atomic_*` RELAXED exactly like `covered_ticks`; a plain torn read would silently drop or duplicate an increment.
- [S2] **Counter-unit migration for in-flight latches:** dedupe can only stop double counting, never lower an accumulated value, so no migration is needed — but QE's `covered_ticks_max`/`SCHED+16..19` expected counts will shift and must be updated in the same QE commit or the class goes red for the wrong reason.
- [S2] **dmesg code collision at SCHED+24:** SCHED's 4000-window is outside `catalog_table_valid()` (:287-297), so a collision renders silently wrong (precedent: +11 vs framebuffer). Verify the whole SCHED base before picking +24 and mirror the severity in `lookup_severity`.
- [S2] **TEMP-DIAG leakage:** the recon trace must be reverted verbatim and grep-verified before the first gate run; a serial trace inside the tick path perturbs exactly the timing-sensitive classes this issue is about.
- [S3] **Doc drift:** `covered_ticks` keeps its name but changes its unit definition; both the hpp doxygen and docs/specs/scheduler.md must state "distinct ticks with the lock held/owned", or the next audit re-litigates the honesty finding.
- [S3] **Rejected alternative recorded, not implemented:** F2 (free-lock non-delivery escalates on a longer bound with an honest message) — still panics on arbitrarily long legal blocks (a harness wait can exceed any bound), needs a new panic path and its own audit; F3 (raise the bound) only postpones the false positive.
