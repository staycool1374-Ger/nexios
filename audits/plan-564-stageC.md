### Verified tree facts at 63199ea16 (read, not assumed)

1. **The retype grammar is complete; the composition is not.** `CAP_RETYPE` = 56 (`syscall.hpp:99`) carves all six kinds; `object_sizing.hpp` fixes `kObjectBytesTcb = 4 * CONFIG_PAGE_SIZE` and `kObjectBytesVSpace = kObjectBytesPageTable = CONFIG_PAGE_SIZE`; `CarvedObjectCap::create` zeroes the payload (`carved_object.cpp:44-70`) with a compile-time `static_assert(sizeof(TaskControlBlock) <= kObjectBytesTcb)` (:38-40). A retyped TCB/VSpace/PageTable is a **Cap over a page range, not a C++ object**.
2. **`VSPACE_MAP` (102) is live and top-down only.** `sys_vspace_map` (`syscall_handlers_vspace.cpp:69-118`) resolves VSpace (WRITE) + PageTable (READ), re-checks the `kCarvedObjectTag`/kind discriminator, refuses a user/kernel `is_user` mismatch, then calls `VSpaceMap::link`. `link()` validates `path_len <= levels-1` before any shift, refuses the kernel half, self-link, and **`vspace_phys == VMM::current_root_phys()` (VSPACE_ERR_ACTIVE_SPACE)**, walks the parent, scrubs the child page and stores exactly one table-link word. `walk_parent` requires every intermediate component present, so links are inherently top-down.
3. **VSPACE_ERR_ACTIVE_SPACE covers only the CALLER's root.** `VMM::current_root_phys()` = `vmm_arch_root_phys(arch::read_cr3())` (`vmm.cpp:593`); `read_cr3` is CR3 / TTBR0 / SATP-phys. A carved root bound to a *non-current* child is invisible to that check, so a live address space could be re-linked after activation. This is the gap the activation registry closes (step 5a).
4. **No activation surface exists, and no arch primitive is needed for one.** `page_table_` is privatized behind `install_page_table` / `swap_page_table` / `clear_page_table` (`task.hpp:549-571`, `task.cpp:1028-1050`) with `ENSURE(page_table_ == 0)` / `ENSURE(new_pml4 != 0)`. The scheduler publishes the field itself at dispatch: `scheduler_switch.cpp:750-757` calls `arch::context_id_tag(next.get_page_table(), publish_context_id_for(next))` into `SwSlots::load_cr3_from`. So activation never has to touch a control register; installing the field plus `pcid_` is sufficient and is arch-neutral by construction (INV-CARVE-6).
5. **The aarch64 trap is real and avoidable.** `arch_page_table_activate()` on aarch64 writes **TTBR1_EL1**, the kernel half (`page_table_impl.hpp:42`), while the task switch uses TTBR0 (`write_cr3`, `io_impl.hpp:314`) and `switch_address_space` (:330) retargets TTBR1 *then* TTBR0 — the issue #524 use-after-free shape. Any activation path that called `ArchPageTable::activate()` on a carved root would repoint the kernel half at a user page: S1. INV-CARVE-6 forbids the call outright.
6. **Teardown assumes PMM ownership of the root and of every leaf.** `complete_teardown` does `VMM::free_user_pages(get_page_table()); arch::context_id_free(pcid_); PMM::free_page(get_page_table());` (`task.cpp:3084-3087`), and `destroy()` ends in `MemPool::free(tcb)` (:3206+, OOM arm at :3215). For a carved space each of those is a double free: root/table pages belong to `CarvedObjectCap` (freed in `dispose`, `carved_object.cpp:72-86`) and leaves belong to `FrameCap`. `VMM::free_user_pages` skips only *kernel-owned* pages, and user Untyped carves are `is_user = true` — so it would free them. A per-TCB ownership discriminator is therefore mandatory, not optional.
7. **`FrameUserMap` maps only into the caller's space.** `FrameUserMap::map` takes `uint64_t pml4 = task.get_page_table()` (`frame_map.cpp`) and derives the VA from the slot index inside the fixed `CONFIG_USER_SHM_VA_BASE` window. The primitive underneath is already general: `VMM::map_frame_from_cap_err(fc, va, user, pml4_phys, executable=false)` (`vmm.hpp`) takes an explicit root and has a transactional rollback (issue #325-A). The foreign-VSpace map surface is therefore a **capability gate plus a registry**, not new VMM code.
8. **Syscall space.** `MAX_SYSCALL = 103` (`syscall.hpp:146`) is the table size; the highest allocated number is `VSPACE_MAP = 102` (:145). Two new numbers means 103/104 and `MAX_SYSCALL = 105`. ## INVARIANTS & CONCURRENCY BOUNDARIES

- **INV-VS-3-prime (amended — the activation guard is spent, not removed).** A carved space becomes a task's address space ONLY through the activation surface (`VSPACE_ACTIVATE` (104) or the composer's internal `CarveBinding::activate`). Activation (a) requires WRITE on the VSpace cap **and** a TcbCap naming the target; (b) operates ONLY on an unpublished target — a task that has never been enqueued or dispatched (`page_table_ == 0`, `pcid_ == 0`, `is_user_ == true`, newborn state, not the caller, not TERMINATED/REAPED) — and refuses a root that is the caller's active space (`VSPACE_ERR_ACTIVE_SPACE`, retained), already activated (`ACTIVATED`), or owned by any published task (`TARGET_REJECTED`); the bare-104 path additionally replicates the composer's kernel-half merge + convergence assert (step 5) so a kernel-half-less root can never reach first dispatch; (c) re-validates the whole subtree top-down through the per-arch codec before install (`SUBTREE_INVALID`); (d) writes **no arch control register**; (e) pins the VSpace cap until the binding drains. The SMP TOCTOU is closed by non-publication, not by locking: the sole user-task publication path is `Scheduler::add_task_err` (INV-CARVE-3, S3-1 — the non-`add_task_err` publishers carry kernel tasks only), so an unpublished target is unreachable by every CPU's dispatcher and no `scheduler_lock_` exclusion is needed on the gate+install sequence. While activated the root refuses links and refuses deletion. The F5 sentence "No carved space is ever activated at F5; M14 inherits the activation guard" is amended to state that M14 *spends* the guard through this surface — never that the guard is deleted.
- **INV-CARVE-1 (composition order is top-down and total).** `retype(Untyped->TCB)`, `retype(->VSpace)`, `retype(->PageTable)` x k, `retype(->Frame)` x m happen first; then `VSPACE_MAP` links intermediates root-first and leaves last (`walk_parent` demands every ancestor present); then `VSPACE_FRAME_MAP` populates the leaves; then activation, last. Any order violation surfaces as `UNMAPPED`/`NOT_TABLE`/`SLOT_OCCUPIED` — typed, never silent.
- **INV-CARVE-2 (no kernel deep copy).** On the carve path the kernel allocates **no** page-table page and **no** address-space page: the composer contains no `PMM::alloc_page`, and `VMM::map_frame_from_cap_err` must never return `VMM_ERR_PAGE_ALLOC` (a walk that has to allocate proves the tree was not pre-linked). `VMM::deep_copy_user_pages` is unreachable from `ProcSvc::fork` when the knob is ON. The kernel stack and kslot window keep their PMM/kslot allocation and are documented as *not* address-space objects (stated, not silently waived).
- **INV-CARVE-3 (atomic composition; unpublished until complete).** The child is not in `all_tasks_` until `Scheduler::add_task_err` (the sole user-task publication path — S3-1; the non-`add_task_err` publishers carry kernel tasks only, excluded by the `is_user_` gate); every earlier failure is one `TaskControlBlock::destroy(child)` plus the rollback guard. No partial child is ever published, no death record is latched, no waiter wakes (INV-PROC-12 preserved verbatim).
- **INV-CARVE-4 (one release point; no touch after drain).** Every cap that keeps a carved child alive (TCB region, VSpace root, m frames) is pinned in exactly one `CarveBinding` slot keyed `(pid, generation)`. The slot is drained exactly once, as the **last statement** of `complete_teardown` — the statement that replaces `MemPool::free(this)`. After the drain nothing may read or write the TCB (its storage may be gone). Double-drain is a generation-mismatch no-op (INV-PROC-5 precedent); the funnel stays index-only.
- **INV-CARVE-5 (generation before publication).** The carved birth site takes its generation from `next_task_generation()` before the child is reachable (INV-PROC-13 extended to every birth site; `clone` already does this at `task.cpp:1833`).
- **INV-CARVE-6 (activation performs no register write; unpublished targets only).** Activation installs `page_table_` + `pcid_` through `install_carved_root()`; the scheduler's existing publication (`scheduler_switch.cpp:750-757`) does the arch part on first dispatch. The "no register write, no flush, no TTBR1 retarget" consequences hold because the target was never live: the bare-104 surface enforces the unpublished gate (`page_table_ == 0`, `pcid_ == 0`, `is_user_`, newborn state) so there is no incumbent context ID to leak (the pcid-leak shape is unreachable — a fresh child has no ID yet) and no live task whose root could be swapped under it. Consequences: no TLB flush at activation (the root was never live), no aarch64 TTBR1 retarget (the #524 shape is unreachable), and `ArchPageTable::activate()` is never called on a user root.
- **INV-CARVE-7 (lock order).** The `CarveBinding` leaf lock is taken alone. The order is `CNode leaf -> s_lock_ (VSpaceMap) -> binding leaf` on the link path, and it is **one-directional**: `vspace_map.cpp` calls only the pure `carve_root_is_activated()` probe, which takes no lock (it reads a per-root atomic flag), so there is no `s_lock_` <-> binding cycle. The binding leaf is never held across `VSpaceMap`/`VMM`/`PMM`, never with `scheduler_lock_`, never from an ISR. `drain_task` runs in teardown context under `IrqGuard` with `scheduler_lock_` released and releases the pins **after** unlocking (a pin may dispose -> `MemPool::free`, LEARNINGS #320).
- **INV-CARVE-8 (ResourceTracker).** Carved pages fold into `track_pmm_alloc/free` (PMM is the only allocation point and already tracks every arm) and descriptors into `track_cap_object_add/remove`. No new counter. `CarveBinding::snapshot_reset()` and `ForeignFrameMap::snapshot_reset()` join the `test_isolate.cpp:1277-1290` cluster, **before** `MemPool::restore_pool_data` (#320).
- **INV-CARVE-9 (arch parity, no new branch).** No `#if defined(CONFIG_ARCH_*)` in any new TU. ## SIL 3 / SAFETY RISKS

- [S1] **Bare-activation live-target swap** — `VSPACE_ACTIVATE` on a published task swaps the root under a live address space (SMP TOCTOU vs the dispatcher, no kernel-half merge, no `is_user_` gate, incumbent pcid leak) — mitigation: the surface is scoped to unpublished targets only (INV-VS-3-prime(b) + INV-CARVE-6: `page_table_ == 0 && pcid_ == 0 && is_user_`, newborn state, non-publication closes the TOCTOU without locking), the bare path replicates the kernel-half merge + convergence assert, and the composer child is the only in-tree caller; `carve_activation_guard` covers the published-target refusal legs.
- [S1] **Double free of root/table/frame pages** — `cleanup()`/`destroy()`/`exec()` free the root via `PMM::free_page` and `free_user_pages` while `CarvedObjectCap::dispose` and `FrameCap::dispose` also free them (user Untyped pages are `is_user == true`, so `free_user_pages` does not skip them) — mitigation: `VspaceKind` plus `release_address_space()` as the single releaser (step 12), `exec` routed through it (step 14), the `TcbStorage` branch in `destroy` (step 13), with `carve_tcb_storage` and tracker delta 0 as acceptance.
- [S1] **An activated root deleted or re-linked under a live task** — `CAP_DELETE` -> `dispose` -> `invalidate_vspace` zeroes the root page while the task runs, and `VSPACE_MAP` could re-link a live space with no flush — mitigation: the activation flag consulted by `link()` (step 5a) and by the delete gate, the `ENSURE(!carve_root_is_activated)` in `dispose`, the binding pin so the last reference cannot be reached while activated, and `carve_activation_guard`.
- [S1] **Stale TLB entry translating a freed page under a live task** — F5 zeroed the page before the shootdown, which is sound only while nothing is activated — mitigation: step 5b moves the full shootdown **before** the zero in both teardown paths, plus `deactivate()`'s own full flush; cited to the M14 handoff (`design-review-558-code-r1.md:20`).
- [S1] **Partial carve published** (INV-CARVE-3) or a leak on the failure path — mitigation: one RAII rollback guard, one `destroy(child)` per failure, one drain path (INV-CARVE-4), and `carve_fork_rollback` at every attempt gate with post-teardown deltas.
- [S1] **TCB region freed while the TCB is still in use** — `drain_task` is the last statement, in exactly the place `MemPool::free(this)` occupied, with the "no read or write after this line" rule, the #409 teardown claim still gating it, and `carve_tcb_storage` asserting exactly-once return of `carved_pages_`.
- [S1] **aarch64 TTBR1 retarget / #524 use-after-free** if any activation path calls `ArchPageTable::activate()` (which writes **TTBR1**, the kernel half) on a user root — mitigation: INV-CARVE-6 forbids register writes on the activation path; the aarch64 publication stays in `scheduler_switch.cpp:750-757` (`context_id_tag` -> TTBR0 with the ASID); `exec`'s `switch_address_space` remains the only TTBR1 retarget and is untouched.
- [S1] **W^X regression** — a carved text region mapped NX (fault on first fetch), a data region mapped executable, or a RO region installed writable — mitigation: executable/writable flags come from the parent's live leaves; executable regions are installed executable-first and never pass through NX (#376); RO goes through `map_page_ro_in_pml4`; aarch64 RO keys on `AP_RO` alone (#376); `carve_fork_parity` compares content **and** leaf permissions.
- [S1] **Lock-order inversion** — binding leaf <-> `VSpaceMap::s_lock_` — mitigation: INV-CARVE-7 (the probe is lock-free; `s_lock_` never takes the binding lock), no binding lock across VMM/PMM/MemPool, pins released after unlocking (#320), never with `scheduler_lock_`, never from an ISR.
- [S2] **Link-registry exhaustion** — `kMaxVspaceMappings` 32 was sized for F5 tests, not for N concurrent carved children — mitigation: `CONFIG_CAP_MAX_VSPACE_MAPPINGS` = 256 with the derivation documented and F9 (#562) named as owner; per-child table count capped (`CONFIG_CARVE_MAX_TABLES`) with a typed `REGISTRY_FULL` fail-closed; `CarveBinding` exhaustion (`CONFIG_CARVE_BINDINGS`) fails closed with `+22`.
- [S2] **Region-enumeration bound** (`CONFIG_CARVE_MAX_REGIONS = 16`) — a legitimately fragmented process would be refused fork — mitigation: typed refusal (never a panic), the bound documented in the spec, and the observed count surfaced in the `+22` payload; raising it is a config change, not a code change.
- [S2] **Fork-path WCET grows** — the content copy is a bounded per-page `memcpy` with no allocation, but it is proportional to the parent's resident regions and runs in caller context — mitigation: knob-gated, documented in 8.8, wall time recorded by the parity class for the F17 (#570) budget; no unbounded loop, no allocation.
- [S2] **Stage B knob flip racing this work** — the carve path is reachable only through `ProcSvc::fork`, so a premature `CONFIG_PROC_MGR` flip would ship the knob-OFF branch — mitigation: `CONFIG_PROC_MGR_CARVE_FORK` has its own default and its own gate; the Stage B flip ordering is unchanged and both flips are one-line reverts.
- [S3] dmesg offset collision for +22/+23 — mitigation: verified free by grepping every `kDmesgBase_TASK +` site; re-grep before commit (#354).
- [S3] `spawn_thread` still leaves `generation == 0` (Stage B drift, out of scope) — the carved birth site does **not** inherit the bug (INV-CARVE-5); recorded so a later reader does not assume thread parity.
- [S3] riscv64 has no ASID in this SATP encoding, so every deactivation is a full `sfence.vma` — accepted; no narrowing attempted (the F5 registry took the same decision).
