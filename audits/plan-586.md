## ROOT-CAUSE HYPOTHESIS (to be convicted in Phase H, not assumed)

The defect is a **test-fixture encoder operand bug on rv64**, not a waitpid/reap defect:
`test_fpu_context_user.cpp:475` emits `addi a1, x0, 0x60` (`rv_addi(11, kOffWaitStatus)`, `kOffWaitStatus == 0x60`) instead of `addi a1, s2, 0x60` (`s2 == kUserDataVa == 0x41001000`).
The aarch64 twin is correct and *asserted*: `:403` `a64_add(1, 19, kOffWaitStatus)` + `:159` `static_assert(a64_add(1,19,0x60) == 0x91018261)`; the rv64 sibling has no counterpart assert.

Consequence chain (all anchors in-tree):
1. `checked(0x60)` is **valid** (`is_user_range`: `0x60 < USER_SPACE_LIMIT 0x800000000000`, `checked_ptr.hpp:73-87`, `constants.hpp:147`) ⇒ `status.unsafe_ptr() == 0x60`.
2. First `sys_waitpid()` iteration: child found, not yet TERMINATED (`:102`) ⇒ status-page pre-cert `:139-144` calls `VMM::virt_to_phys_in_pml4(0x60, cur->get_page_table())`. rv64 `L0[0]` carries **explicit leaves only** (virtio-mmio 0x0A000000, PLIC, UART, ECAM, one 4 KiB RTC page at 0x101000; `boot.S:180-200`, "VA 0 still faults") ⇒ `0x60` unmapped ⇒ returns **0** ⇒ `sys_waitpid` returns `SYS_ERR_GENERIC_FAIL` **before** `waiting_child_pid`/`BLOCKED`/`dequeue_ready`.
3. Parent stores `wait_ret = FAIL` (`:480`), writes done-magic, exits 0 ⇒ `:1005`, `:1006`, `:1009` pass; `:1007` `fork_ret != wait_ret` FAILS; `:1008` never sampled (so `wait_status == 0` is currently *vacuous* on rv64).
4. The child is never collected by waitpid. It is not reapable by the tick reaper while the parent is live (`scheduler_lifecycle.cpp:610-624`, issue #221 zombie semantics; reapable only once the parent is TERMINATED) ⇒ at teardown the TCB still exists ⇒ `LEAK: PMM +34, Tasks +1, MsgQueues +1, Notifies +1, EventGroups +1`, deterministic because `0x60` is statically unmapped.
5. The child does **not** re-issue FORK: `syscall_entry.S:206-209` advances `sepc` by 4 before the C dispatch, and `task.cpp:1996-2004` copies the frame + zeroes `X10/A0` (`frame[9]`) ⇒ exactly one child (matches `Tasks +1`, not `+N`).

## INVARIANTS & CONCURRENCY BOUNDARIES
- **INV-WAIT-1 (kernel, must not be weakened):** a user `status` pointer is written only after (i) `is_user_range` (`checked`) and (ii) a MAPPED pre-certification in the caller's PML4 (`syscall_handlers_process.cpp:139-144`); fail direction is *return failure, mutate nothing*. The fixture must satisfy (i)+(ii); the kernel must not be relaxed to satisfy a broken fixture.
- **INV-WAIT-2:** the pre-cert runs **before** `waiting_child_pid = target_pid` / `dequeue_ready` / `state = BLOCKED` (`:132-147`) ⇒ a rejected status pointer leaves no wait state, no ready-queue mutation, no wake obligation. Phase H must observe this (no scheduler mutation on the failing path).
- **INV-WAIT-3:** the reap (`:122-127`) is ordered *after* the status write; a status-copy failure leaves the zombie linked to a live parent (deferred by design, `scheduler_lifecycle.cpp:614-624`), and re-become reapable the moment the parent terminates. Nothing in this plan changes that ordering.
- **COW boundary:** the harness may only pre-seed the *parent's* data page via the HHDM alias before the parent forks (`fpu_fork_spawn` returns, `:956`, before `Scheduler::reschedule()` at `:958`). A pre-seed after the fork lands in either side's private copy nondeterministically.
- **Irq/lock boundary:** unchanged — no `IrqGuard`, no spinlock, no allocation, no new global, no new syscall on any path. The only edits are `constexpr` word builders and one emitted instruction word.
- **Arch boundary:** edits are inside the existing `#else /* CONFIG_ARCH_RISCV64 */` block (`:417-493`) and its builder section (`:163-204`); the file itself is guarded `:44` `#if defined(CONFIG_ARCH_AARCH64) || defined(CONFIG_ARCH_RISCV64)` ⇒ x86_64 translation unit and aarch64 words are byte-identical.
- **Assertion strength:** none of `:1000-1012` is weakened, reordered, or deleted; the optional sentinel only makes `:1008` strictly stronger (it can newly fail where it previously passed silently).

## SIL 3 / SAFETY RISKS
- [S2] The failing assertion masked a **vacuous** status check: `wait_status == 0` (`:1008`) also passes when the kernel never delivered a status at all — mitigation: step 12 sentinel pre-seed, converting "never written" into a hard failure; without it, a future regression in the status-delivery path stays invisible on both off-x86 arches.
- [S2] Fixing the fixture must not be smuggled in as a kernel relaxation: any change to `sys_waitpid`'s `is_user_range`/`virt_to_phys_in_pml4` gate (e.g. "ignore the status pointer when it is unmapped") would hand a user task a kernel-side write into an unmapped/foreign VA and break INV-WAIT-1 — explicitly out of scope, auditor-blocking if attempted.
- [S2] Latent kernel hazard surfaced by this hunt, **not fixed here**: `Scheduler::wake_waiting_parent` writes `*p->waiting_child_status` under `stac` with no `NEXIOS_FAULT_RECOVERY` arm (`scheduler_lifecycle.cpp:412-419`) on the strength of a pre-cert that proves MAPPED but not WRITABLE — a user task passing a mapped read-only page as `status` would take a kernel store fault in the wake path. Mitigation: file a separate issue (same class as MP-4/SMAP discipline); never fold it into #586.
- [S2] Fixture-encoder class defect: word builders that compute a pointer operand have no `static_assert` on the rv64 side (aarch64 has one at `:159`), which is precisely how `:475` survived review — mitigation: step 9 adds two asserts, and step 13's grep proves no other `rv_addi(<arg-reg>, offset)` site exists in `src/kernel/test/`.
- [S3] Leak boundedness (so #586 is an S2, not S1): a zombie of a live parent is deferred by design and becomes reapable once the parent terminates (`scheduler_lifecycle.cpp:594-629`); the +1 task in the failing run is a teardown-boundary residue, not an unbounded leak.
- [S3] Documentation: the doc-block extension (step 11) is the only durable record that the test was changed for a fixture reason; without it the next reader sees an unexplained diff in a read-only-by-policy tree.
