## Scope of the change (src/ only)

1. `src/kernel/arch/aarch64/interrupt_controller.cpp` — `aarch64_el0_fault_handler`: new whitelisted ESR-decode delegation block calling `PagerRegistry::delegate_fault` before debugger routing/kill; both fault-kill legs (trip + main) now call `Scheduler::terminate_err_from_trap` before `switch_away_from_terminating[_discard]`.
2. `src/kernel/arch/riscv64/interrupt_controller.cpp` — `riscv64_u_fault_handler` + `riscv64_exception_dispatch` (U-mode/trip legs): new scause-whitelist delegation block; all three kill legs call `terminate_err_from_trap` before the deferred switch.

4. No changes to `src/kernel/kernel.cpp` (x86), `src/kernel/ipc/pager_registry.*`, or any other `src/` file.

## Checks

### (a) Fault-code whitelist cannot turn a fatal fault into a pager-block — PASS

- **aarch64:** `EC == 0x24 || EC == 0x25` (data abort) + `(DFSC & 0x3C) == 0x04` (DFSC `0b0001xx` = translation fault, levels 0–3). Permission (`0x0C–0x0F`), access-flag (`0x08–0x0B`), address-size (`0x00–0x03`), and external faults fail the mask at the ESR level. Instruction aborts (`EC 0x20/0x21`) fail the EC level. `0x25` is unreachable from EL0 (stated in the comment) and therefore harmless.
- **riscv64:** `scause == 13 || scause == 15` (load / store-AMO page fault). Instruction page faults (12), misaligned (4/6), access-faults (5/7), illegal-instruction (2), and ecalls (8/9) fall through to kill.
- **Defense in depth (the deciding factor):** both shims synthesize an x86-shaped `#PF` code with `P=0, RSVD=0, I/D=0, U/S=1` (`pf_code = (W<<1)|(1<<2)`) and pass the real fault VA (`far`/`stval`) as `cr2` into the **unchanged** `delegate_fault` classifier, which re-validates F3 (P==0), F4 (RSVD==0), F5 (U/S==1), F6 (I/D==0), and F7 (`cr2 < USER_SPACE_LIMIT`). Even a mis-decoded ESR/scause cannot delegate a permission, instruction-fetch, reserved-bit, or kernel-half fault — the classifier fails it closed to SIGSEGV. Kernel-half FARs are rejected by F7.
- **No-registration path:** `delegate_fault` returns false → falls through to the pre-existing kill, which is structurally byte-identical (same TERMINATED+exit-code+wake+deferred-switch shape, now via the helper). Existing EL0/U-mode fault tests with no pager registered are unaffected by construction.

### (b) `delegate_fault` try_lock fail-closed preserved on the new call paths — PASS

- `pager_registry.cpp` is **untouched** by this patch. `delegate_fault` still uses `s_lock_.try_lock()` with fail-closed `return false` (lines 502–503) from ISR context, with the S1 rationale comment intact. The aa64/rv64 shims are pure new *callers* of the same function; no new lock is taken around the call (aa64 shim takes none; rv64 shim runs in the existing trap-handler context). No new lock-order edge is introduced. Verified-correct element #2 of the #107 audit is preserved.

### (c) `terminate_err_from_trap` never switches/frees, takes no reentrant locks, zombie-before-arm holds — PASS

- **No `switch_to_task` / `free` / `cleanup`:** verified by body inspection — the helper performs exactly `validate_task_ptr` → `IrqGuard` → remote-current refusal → `ENSURE(lock depth 0)` → `SchedulerLockGuard` → `charge_exec` → `dequeue_ready` → `TERMINATED` + `exit_code` → `thread_join_note_termination` → `wake_waiting_parent` → `teardown_step(Terminate)` → `release_zombie` → reaper poke → return. This is the `terminate_err` prefix minus the self-current switch block (lines 119–149 of `terminate_err`), nothing more.
- **No reentrant locks:** single `SchedulerLockGuard(scheduler_lock_)` acquisition guarded by `ENSURE(scheduler_lock_depth_own() == 0)` (CODING_STYLE §11-conformant, mirrors `terminate_err` and `switch_away_from_terminating`). Callees are the same ones `terminate_err` already calls under the same lock (`wake_waiting_parent` → `find_task`/`set_task_ready`, `release_zombie` → leaf `zombie_lock_` in global→leaf order, reaper `notify` leaf-only). No new lock-order edge vs the audited `terminate_err`.
- **`[[nodiscard]]` discipline:** all four call sites capture the return into `trap_term_err` and `(void)`-consume it with a comment explaining refusal is impossible (task == current). Compiles under `-Werror=unused-result`.
- **Zombie-before-arm:** `release_zombie` (which runs `invalidate_pending_switch_to`, `scheduler_lifecycle.cpp:85`) executes inside the helper; the deferred-switch arm is published afterwards by the caller's `switch_away_from_terminating[_discard]`. Traps are masked in fault context, so no same-CPU tick can interleave between prefix and arm; cross-CPU observers see the same release-then-arm window as the audited `terminate_err` path.
- **Liveness precondition ("task must be live") holds on all four legs:**
  - Main legs (aa64 EL0, rv64 U-mode) are guarded by `t != nullptr && is_valid(t) && t->state != TERMINATED` — the same guard that previously guarded the raw kill.
  - Trip legs dereference `current_task()` unchecked (as did the pre-patch code), but `trap_owner_trip` (`scheduler_integrity.cpp:367-374`) **refuses dead tasks**: `!trapped_valid || !is_user_ || state == TERMINATED → PARK`. Any trip leg that reaches `terminate_err_from_trap` has therefore passed the repair path, which guarantees a live, non-TERMINATED user task. Double-`release_zombie` (which has no idempotency guard) is unreachable. The added `ENSURE(validate_task_ptr)` converts the old silent-corruption shape into a fail-stop, which is strictly safer.

### (d) Trip legs still discard-correct — PASS

- Both trip legs (aa64 `switch_away_from_terminating_discard`, rv64 `switch_away_from_terminating_discard`) keep the `_discard` variant, as before. The helper runs *before* the discard arm is published and does not itself publish any save target, so the live-RSP-must-not-be-published invariant (issue #513 2.11) is undisturbed. The rv64 native-leg trip/main structure is unchanged apart from the two insertions.

### (e) No x86 behavior change — PASS

- The diff touches no x86 file (`kernel.cpp`, `arch/x86/*`, IDT/syscall paths untouched — confirmed via diff file list). The x86 `#PF` arm (delegate-before-debugger-before-signal at `kernel.cpp:2573`, guard check in the separate kernel-mode branch) is byte-identical. x86 gates (`cap_pager` 15/15, `capability` 169/169) corroborate no regression.

### (f) Cross-arch parity complete — PASS

- Both secondary arches now have (i) a per-arch fault-decode → `delegate_fault` shim and (ii) the full trap-safe termination prefix. x86 already had both (delegate via the #PF arm; full termination via the signal-delivery path). No arch is left with the old TERMINATED-without-release shape. Per-arch decode is correctly non-shared (ESR vs scause), per AGENTS.md parity rules (same capability in the same cycle, arch-appropriate mechanism).

## Observations (non-blocking, no action required in this change)

- **O1 — debugger-ordering asymmetry (aa64 vs rv64):** aa64 delegates *before* debugger routing (matching x86 `kernel.cpp:2573→2597` order); rv64 delegates *after* debugger routing. For a task that is both debugger-attached and pager-registered, rv64 parks while aa64/x86 delegate. Debugger-attached + pager-registered is a test-only combination; either order is defensible, but a future cleanup should pick one order on all three arches.
- **O2 — guard-page faults delegate first on all arches:** the aa64 stack-guard arm now runs after delegation, matching the pre-existing x86 shape (from-user branch returns before the guard check). A pager could therefore be offered a guard-range VA, and `SYS_PAGER_MAP` has no guard-range reject (F10 covers canaries only). This exposure is pre-existing on x86, now consistent across arches — noted as a possible follow-up hardening, not a defect of this patch.
- **O3 — gates are developer-reported:** this read-only audit verified code and ordering statically; it did not re-execute QEMU classes or the style checker. The claimed style Errors 0 and the gate matrix (including the #527/#528 follow-up attributions) are taken as stated.

## DECISION

**DECISION: APPROVED** — the whitelist decode is fail-closed at two independent levels (arch whitelist + unchanged F3/F5/F6/F7 classifier), the ISR `try_lock` discipline is untouched, the new termination prefix is a strict minus-switch subset of the audited `terminate_err` with zombie-before-arm ordering and a provably live precondition on all four legs, trip legs keep the discard variant, x86 is untouched, and cross-arch parity is complete with no regression of the #107 verified-correct elements.
