## PRIOR S2 — RESOLVED
`rd_verify_entries(RdDirEntry *dir)` (ramdisk_fs.cpp:291-304) verifies the freshly-loaded LOCAL array
(`rd_ensure_cached`'s stack `dir[]`, :350) BEFORE the install critical section publishes `rd_cached=true`
(:378 verify → :379-387 publish). It touches no shared state — `rd_compute_crc` is pure block-IPC
(never under `rd_lock`). AUDIT of every `rd_cached = true` site (grep: :368, :385):
  - :368 empty/degraded/fail-closed path → installs an all-zero `rd_dir` (no `RD_ENTRY_VALID` entry) → nothing to expose;
  - :385 verified path → array is fully verified before publish.
Every other writer is fail-closed or trivially consistent: `rd_create` publishes an empty-size entry whose
CRC is `finalize(INITIAL)==0` == `rd_compute_crc(start,0)` (:716); `rd_file_write` CLEARS `VALID` on any
`count>0` (:570); `rd_flush_entry` recomputes and stores the matching `crc32` before setting `VALID`
(:320-326); `rd_unlink` zeroes the slot. Mutation paths only ever set `rd_cached=false`, never `true`.
Therefore the documented precondition "`rd_cached == true` ⇒ every visible entry is CRC-verified" is SOUND:
a concurrent `rd_lookup`/`rd_readdir` reads `rd_dir` only after its own fill returns (its own verified copy,
or a first-published verified/empty view), so no interleaving exposes an unverified `RD_ENTRY_VALID` entry.
No path publishes `rd_cached=true` with unverified visible entries. S2 closed.
