## Fix summary (as claimed)

1. `Scheduler::set_current` refuses to link outgoing TCBs with `find_task(old->id) != old` (mirrors the H2 ownership guard in `enqueue_ready`). Trigger was an unregistered impersonated task entering dispatch via `enqueue_ready_inner`, then applied unconditionally by the aarch64 epilogue.
2. `irq_context_switch_common` (aarch64 `vectors.S`) now calls `scheduler_validate_pending_switch` after saving SP; on 0 calls `scheduler_abort_switch_fixup` and resumes via `.restore` with SP untouched. Mirrors `x86_64/isr_stubs.asm` + `riscv64/syscall_entry.S`. Closes the file's own documented S3 gap.

## Check results

### (a) zombie-before-arm / arm-cancel ordering — PASS

- `set_current`, both paths (same-task early return `:215-224` and switch path `:226-253`), clears all four switch atoms + bumps nothing, then calls `restore_preempted_current(old, armed)` — arm-cancel strictly before any re-enqueue. The new guard (`:278-285`) only selects *which* re-link runs (`enqueue_ready_inner` vs flag-clear); it does not move, skip, or duplicate the cancel/restore sequence.
- aarch64 abort path delegates cancel + publish-side-effect undo to the shared validator (`global_state.cpp:596-633` `drop_arm` → `cancel_pending_switch` → `restore RUNNING` + dequeue + target re-enqueue), identical to the x86/riscv abort. `cancel_pending_switch` (`scheduler_switch.cpp:87-111`) additionally republishes the trap-entry kstack slot for the continuing task (site 3), so no stale-slot arm survives the abort.
- No termination-path ordering touched (the #523 `terminate_err_from_trap` zombie-before-arm shape is unaffected — this diff adds no terminate/kill site).

### (b) Register preservation across the two new `bl` calls — PASS

- At `irq_context_switch_common`, all user GPRs are already in the `save_all` frame; the only live values are `x0` (save-slot pointer, consumed by `str x1,[x0]`) and `x1` (SP, stored). Both are dead before the first `bl` and re-derived via `adrp` afterwards — nothing live spans either call.
- `x30` dead: clobbered by the preceding `bl handle_gic_irq`; epilogue terminates in `eret`, never `ret`; `restore_all` reloads `x30` from the frame (`[sp,#240]`). Callee-saved `x19-x28`/FP preserved by the C callees per AAPCS64; no asm frame adjustment around the calls, so SP stays 16-byte aligned (`save_all` subtracts 288 ≡ 0 mod 16; neither callee affects caller SP observably).
- Matches the riscv precedent (only `sp` live, `ra` stashed) and is strictly safer than x86 only in that x86 must push caller-saved regs because its ISR frame keeps `rax` live — here there is nothing to push. No `DAIF`/`SPSR_EL1`/`ELR_EL1` touched by either callee.

### (c) Abort path leaves SP untouched, reaches `restore_all` + `eret` — PASS

- `.Lswitch_abort` executes only `bl scheduler_abort_switch_fixup; b .restore`. No `mov sp, x1` precedes it (the load happens only on the apply path). On aarch64 the fixup is a no-op (`global_state.cpp:696-711`, `#else (void)0` — TSS rebind is x86-only), so SP provably still addresses the interrupted task's `save_all` frame at `.restore`, which runs `restore_all; eret`.
- Validator-on-abort contract holds: returns 0 only after `cancel_pending_switch()` (all atoms cleared, `next_task_id = UINT64_MAX`) plus publish-side-effect undo. The `.Lswitch_abort` comment's "already invalidated the atoms" is accurate.
- `el0_sync` fault entry (`b irq_context_switch_common` after the C fault handler) shares the frame-intact precondition (`save_all` done, `x0/x1` dead) — safe.
- Note: the "Rebind arm-side redirects" comment slightly overstates what the no-op fixup does on aa64, but the underlying claim is covered: arms no longer publish `load_kstack_*`, and `cancel_pending_switch` republishes the entry slot for the continuing task (site 3), so there is no stale-slot redirect to rebind. Harmless prose, no correction required.

### (d) `set_current` guard cannot strand a legitimately unregistered current — PASS

- Production `set_current` callers enumerated: `scheduler_switch.cpp:470` (owner-resolve: owner owns the live RSP or is the harness — registered in practice; a running stack implies a dispatched, hence registered, task), `test_sched_helpers.hpp` (`yield_as`/`yield_to_task`/`ScopedCurrentTask`), `test_isolate.cpp:1715` (target drawn from `all_tasks_` iteration, i.e. registered), plus test-only impersonation fixtures.
- Impersonation direction verified: scope *entry* enqueues the harness (registered → guard passes, unchanged); scope *exit* is exactly the fixed case (old = unregistered fixture → now refused instead of orphan-linked). Strictly fewer queue insertions; the harness-queued-while-current residue at exit is pre-existing, unchanged, and healed by the specified `next_task` candidate==current evict branch (covered by `scheduler_evict_queued_current_drops_safely`).
- Registered-task behavior bit-identical: `create_test_task` fixtures register via `register_task`, so `find_task(id) == ptr` holds and the `set_current` consume/restore tests (`scheduler_evict_current_then_rescued`) are unaffected — consistent with the claimed green gates.
- Early-boot paths use raw `set_current_ptr` (`scheduler_registry.cpp`, `scheduler_lifecycle.cpp`), never the guarded `set_current` — no boot-current stranding possible.

### (e) Cross-arch parity (x86/riscv unchanged) — PASS

- No x86/riscv file touched. The shared `set_current` change narrows enqueue eligibility identically on all arches and mirrors the pre-existing `enqueue_ready` H2 guard (`scheduler_queue.cpp:275-300`) including its refuse shape (`in_ready_queue_ = false`, no link). x86/rv64 previously survived the same orphan one tick later via validator-abort + `drop_arm` re-enqueue; they now never form the arm — a strict reduction of bad arms, no new divergence.
- The aarch64 epilogue is now shape-equivalent to both peers (validate → apply / fixup → restore). Deferred deltas (generation re-check, ISR-nesting-depth guard) are explicitly documented in the new comment and vacuous on this path today: exceptions mask IRQs on entry and this is the single-CPU masked epilogue, so no concurrent publisher can tear the pair between check and apply. Acceptable tracked follow-up, not a parity violation (see S3-3).

### (f) No new dynamic allocation / IRQ-enable / lock-order hazards on the trap path — PASS

- Validator: atomics + bounded lock-free `id_table_find` (probe loop bounded by `ID_TABLE_SIZE`, no locks — prior audit finding, unchanged) + lock-free runq ops + ISR-safe `Logger::raw_write`. Runs with IRQs masked (interrupt gate); no enable, no sleep, no pool/heap, no `new`/`malloc`/`free`.
- `set_current` addition is one bounded table lookup (`find_task`), same lock posture as the existing `yield_to_task` entry guard (`test_sched_helpers.hpp:77`).
- Arm-cancel path takes no new locks; ordering vs `scheduler_lock_` unchanged (trap path takes none, as before).

## Findings (all S3, non-blocking — no correction patch required)

- **S3-1** — `set_current` refusal branch clears only `in_ready_queue_`, leaving `rq_priority_`/`ready_deferred_` uncleared (the accept branch clears both). Consistent with the `enqueue_ready` refusal precedent (`scheduler_queue.cpp:297`), and an unowned task cannot hold `ready_deferred_` (ownership is checked before deferral at `:275-300`), so unobservable in practice. Suggested hygiene only.
- **S3-2** — `[H2-ABORT]` serial write in the validator (`global_state.cpp:664-678`) is unconditional while `[H2-DEAD]` is `CONFIG_DEBUG_IPC_SCHED`-gated. Cold path (abort only), ISR-safe sink per precedent; at most a timing perturbation on an already-aborted switch. Suggested: gate it identically.
- **S3-3** — Generation re-check + ISR-nesting-depth guard remain absent on the aarch64 epilogue (tracked follow-up, single-CPU-masked justification documented in-file). Revisit when SMP/AP paths arm switches on aa64; the validator's AP `drop_arm` skip (`cpu_index() != 0 → return`, arm left pending) is shared-shape with peers and correct today.

## Decision

**DECISION: APPROVED** — the trigger fix (ownership guard) and the apply-side fix (shared validator + abort) are both correct, minimal, and parity-restoring; all six safety checks pass with no S1/S2 findings. No `rejected_patch` generated (nothing to correct).
