## FINDINGS
- [S3] src/services/terminal/framebuffer.cpp:57 — dual-window rollback leaks the current page's identity mapping when the HHDM twin fails
  WHY: The failure branch rolls back only `u < page`, so if `map_page_err(page,page)` succeeded but `map_page_err(HHDM+page)` failed, the identity leaf for `page` stays mapped while init returns false.
- [S3] src/kernel/memory/vmm_cap.cpp:107 — `unmap_mmio_from_cap_err` lacks the virt+size wrap guard its map twin has
  WHY: `map_phys_range_try` rejects `page_count > (UINT64_MAX - virt_addr)/PAGE_SIZE`, but the unmap verify/clear loops compute `virt_addr + i*PAGE_SIZE` with only a size-overflow guard, so a near-top VA with multi-page size could wrap (unreachable from current callers, who pass the successfully mapped VA).
- [S3] src/kernel/test/test_vmm.cpp:175 — revoked-cap coverage proves NOT_MAPPED-after-revoke, not OK-after-revoke on a present leaf
  WHY: The test revokes after the range was already unmapped, so the headline contract (unmap-after-revoke clears a present leaf, no REVOKED check) has no OK-path assertion; consider map → revoke → unmap → OK.
- [S3] src/kernel/driver/ahci.cpp:100 — teardown unmaps the identity window while port_init mapped the HHDM window (pre-existing mismatch, new miss-logs may mislead)
  WHY: `port_init`/rollback map and unmap `HHDM_OFFSET + phys`, but `~AhciDriver` calls `unmap_page_err(phys)`; behavior is unchanged from the void baseline (same twin does the clear, free stays unconditional), but a NOT_MAPPED "miss" log there reports the wrong window, not a real hole.
