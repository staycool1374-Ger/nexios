## INVARIANTS & CONCURRENCY BOUNDARIES

- **INV-DERIV-1 (lock order, leaf discipline — r2: ranked).** `derivation_lock_` is declared `sync::SpinLock lock_{LockRank::Leaf}` (rank 3, innermost, `spinlock_order.hpp:34-39`); `CNode::lock_` stays `Unranked` (`cap.hpp:65`) as today. The two are **never held simultaneously**: every derivation mutation runs with no CNode slot lock held (`record` after `install()` returns; `forget_slot`/`remove_if` after the slot critical section exits and before `release()`). With `Leaf` the M2 §6.2 check (`spinlock_order.cpp:144-166`) now *reports* any future nesting of `derivation_lock_` inside another `Leaf` (`outer >= inner`, `:155-158`) instead of silently accepting it. Cap ops are task-context only (`ramdiskd` is a daemon task), so no `IrqGuard` on any arch (contrast LEARNINGS #34, IRQ-reachable locks).
- **INV-DERIV-2 (reference accounting).** The table holds **no** `KernelObject` references and **no** raw `CNode*` across calls. Pointers used in a walk are obtained live (`cap::lookup` pins, released exactly once on every exit path) or are the walk's own item. `take_child` transfers the edge out and returns value data only. Consequence: no double-free, no dangling `CNode*`, stack-allocated test CNodes (`test_cap_lifecycle.cpp:114-145`) can never be pinned past their frame.
- **INV-DERIV-3 (bounded derivation depth, creation-enforced — r2: §4.3 mapping stated).** `child_depth = derivation::child_depth(parent) + 1` must be `<= CONFIG_CAP_MAX_DEPTH` (8, `nexios_config.h:581-582`) or the creating op fails closed with `CAP_ERR_DEPTH_EXCEEDED` — including retype (step 9 computes the depth generically, so carve-chains bound correctly). §4.3's *depth* clause ("revocation depth is bounded by `TBD at API freeze`", `:252`) is therefore satisfied constructionally and strictly stronger than a revoke-side check; the companion clause ("a revoke that exceeds the bound returns a typed error and is resumable", `:253`) is satisfied on the dimension that *can* be exceeded at run time — the per-call work budget (**INV-DERIV-4/11**). Both halves are implemented; the wording sync is step 16/Q2.
- **INV-DERIV-4 (bounded work — single bounded loop).** `kCapMaxDerivations = 256` entries, `kRevokeEdgeBudget = 64` edge-takes per call, loop bound `kRevokeMaxSteps = 2 * kRevokeEdgeBudget + 4` (= 132; the proof allows `2B+2`, so the guard is unreachable-with-slack). Per call: ≤ 64 takes × ≤ 256-entry scan = **≤ 16 384 comparisons**; every loop iteration either takes one edge (≤ 64) or pops one stack entry (≤ pushes ≤ takes), so iterations ≤ 2B+2. No allocation, no recursion, no `while(true)` (CODING_STYLE §6). Step-bound exhaustion ⇒ `CAP_ERR_DERIVATION_CYCLE` (corrupt-table guard, must be unreachable).
- **INV-DERIV-5 (no amplification — the point of the issue).** `CAP_DELETE` never calls `target->revoke()`; other holders' `lookup()` keep succeeding. `CAP_REVOKE` never marks the named cap's target revoked and never touches a slot with no derivation edge from the named cap. The old object-wide behaviour survives only as `cap::revoke()` (`cap.cpp:197-233`), reachable from kernel teardown (`ramdiskd.cpp:163`) and tests — never from a user-visible operation.
- **INV-DERIV-6 (test-isolation soundness, HARD dependency).** `test_isolate` byte-rewinds MemPool ⇒ slot generations are rewound, so a stale edge could match a *live* slot of the next test. `cap::derivation_snapshot_reset()` (production TU) MUST be called from `snapshot_restore()` beside `cap::FrameUserMap::snapshot_reset()` (`test_isolate.cpp:1275`) **before** `MemPool::restore_pool_data()` (`:1444`). Merge gate, not a follow-up.
- **INV-DERIV-9 (post-order destruction, root exemption — r2, resolves S1).** *No cap slot is removed until every derivation edge whose parent is that slot has been drained; the named root slot is never removed.* Induction: base — a leaf item yields no children, so its slot is removed immediately, which destroys an object that has no surviving derivations. Step — assume the invariant holds for every item of depth > d; an item at depth d drains its child edges one at a time and each drained edge is fully processed (by the hypothesis) before the next is taken; when `take_child` reports none, every derivation of the item's cap is destroyed, so removing its slot destroys nothing reachable. Therefore a revoke seeded at the named cap reaches **every** derivation at **every** depth, and the named cap survives (§4.3 `:250-251`, INV-MK-7 `:80`). Corollary used by step 5: `forget_slot` inside `CNode::remove` can only prune edges that are already consumed at that point, so the prune hook is behaviour-neutral for the walk and remains the leak-closer for delete/dispose/teardown.
- **INV-DERIV-10 (validated, gen-pinned walk — r2, resolves S2-2).** The named slot is validated **and pinned** in one `cspace->lock_` critical section; the walk then uses the **captured** `(cspace->serial(), slot, gen)` triple and never re-reads live slot state to widen the match; after the walk the slot is re-validated under the same lock (occupied ∧ `gen` equal ∧ same target pointer) and any mismatch returns `CAP_ERR_BAD_HANDLE`. Destroying a child therefore goes through `remove_if(slot, gen)` (never plain `remove`), so a slot recycled between take and destroy is never deleted. Net: no wrong-success, no deletion of a foreign cap (INV-MK-9 `:81`, deny-never-degrade).
- **INV-DERIV-11 (monotone, resumable revoke — r2, resolves S2-1).** Every edge take is destructive and every destroy is unconditional; a call that returns `CAP_ERR_REVOKE_INCOMPLETE` has therefore destroyed a (possibly empty) prefix of the derivations and left every not-yet-taken edge intact (the abort happens *before* the take). Re-invocation from the same named cap continues, so repeated calls converge in ≤ ⌈edges / kRevokeEdgeBudget⌉ invocations. A call never reports success while derived caps survive, and never reports failure after destroying a cap the caller could still reach.
- **INV-DERIV-7 (accounting unchanged).** No new resource type: the table is static bss, so `ResourceTracker` counters and the `test_isolate` snapshot layout are untouched; only the pre-existing `track_cap_slot_add/remove` fire for removed slots. `revoke_derivations` on a cap with no derivations is a no-op ⇒ expected delta 0.
- **INV-DERIV-8 (no RT-path allocation / no build divergence).** No `MemPool`/`PMM`/heap use on any new path (CODING_STYLE §4). `CONFIG_DEBUG` adds only `Logger::error(error_string(err))` on failure paths (precedent `syscall_handlers_cap.cpp:143-148`); control flow, failure policy and state transitions are identical in both builds (CODING_STYLE §6).

8. **`cap.cpp` — `revoke_derivations()` (r2: rewritten post-order walk with validation locking, root exemption and a per-call budget).**
   - **8a Validate + pin under `cspace->lock_`.** `cspace` null / `!slot_index_valid(handle_slot(handle))` / `handle_cspace(handle) != cspace->cspace_id` ⇒ `*err_out = CAP_ERR_BAD_HANDLE; return -1;` (no lock taken). Then one critical section: `CSlot &s = cspace->slots[slot]`; unoccupied or `handle_gen(handle) != s.gen` ⇒ `CAP_ERR_BAD_HANDLE`, `-1`; otherwise `if (!s.obj->acquire())` ⇒ `CAP_ERR_BAD_HANDLE` (revoked target, mirror `lookup()` `:169-195`), capture `named_target = s.obj` and **`named_gen = s.gen`** (the *captured* gen, never re-read).
   - **8b Root pin.** `if (!cspace->acquire()) { named_target->release(); *err_out = CAP_ERR_BAD_HANDLE; return -1; }` — the caller's cspace is TCB-owned (`task.cpp:266-274` `ensure_cspace`/`attach_object`) and the pin makes the walk independent of that argument (INV-DERIV-2). Also initialise `uint32_t budget = kRevokeEdgeBudget; uint32_t destroyed = 0;`.
   - **8c Work item + stack.** `struct WorkItem { CNode *node; uint32_t slot; uint32_t gen; bool owns_pin; bool is_named_root; };` `WorkItem stack[CONFIG_CAP_MAX_DEPTH + 1]; uint32_t sp = 0;` seeded `{cspace, named_slot, named_gen, /*owns_pin=*/false, /*is_named_root=*/true}` — the named root's reference is the 8b pin, released unconditionally at exit; `owns_pin` marks the per-child `lookup()` pin. `static_assert(CONFIG_CAP_MAX_DEPTH + 1 <= kCapMaxDerivations)`.
   - **8d Bounded loop (drain-then-remove).** `for (uint32_t steps = 0; steps < kRevokeMaxSteps; ++steps)`: `if (sp == 0) ⇒ finished`; `WorkItem &top = stack[sp-1];` if `budget == 0 && derivation::has_child(*top.node, top.slot, top.gen)` ⇒ **`CAP_ERR_REVOKE_INCOMPLETE`** (INV-DERIV-11; unwind per 8f, remove nothing further); `DerivationEdge e; if (!derivation::take_child(*top.node, top.slot, top.gen, e))` ⇒ **this item is fully drained**: `if (!top.is_named_root) { if (top.node->remove_if(top.slot, top.gen)) ++destroyed; }` (post-order destroy, gen-checked; `false` means the cap already went away and its edges were pruned), `if (top.owns_pin) top.node->release();`, `--sp`, `continue`. Otherwise `--budget;` and resolve per 8e. **Never** call `remove`/`remove_if` on an item that still has child edges, and **never** on `is_named_root` (root exemption, §4.3 `:250-251`).
   - **8e Resolve child.** `e.child_node_slot == kDerivSelfNode` ⇒ `child_node = top.node; owns_pin = false;` (retype self-edge: same CNode, the item's/root's pin covers it). ## SIL 3 / SAFETY RISKS

- **[S1] Premature prune ⇒ silent depth-1 revoke (the r1 blocker).** Eager child-slot removal would prune grandchild edges before the walk takes them, so a chain A→B→C revoked at A destroys B and silently leaves C live with a success return — wrong-success on a safety function (§4.3 `:250-251`, INV-MK-7 `:80`, §10 D4 `:725`). — Mitigation: **INV-DERIV-9** (post-order drain-then-remove + root exemption, steps 8c-8d) with the induction proof; step 5's prune hook is behaviour-neutral under post-order (corollary stated at each hook); `cap_revoke_derivation_depth_bound` (explicit 8-link construction) is the merge gate that fails under the r1 order.
- **[S1] Partial revoke is an observable intermediate state** (some derivations destroyed, some not) — the direct consequence of implementing §4.3's resumable clause (`:253`). — Mitigation: **INV-DERIV-11** — the abort happens strictly *before* the take, so no edge is ever lost; every return is either `OK` (nothing reachable survives) or `INCOMPLETE` (retry converges); stale handles fail closed in `lookup()` (gen mismatch), so no caller can act on a half-revoked cap; the typed error is a debug-log diagnostic while the syscall face stays `-1` (no false success).
- **[S1] Stale derivation edge matches a live slot after `snapshot_restore`** (the MemPool byte-rewind rewinds slot generations, so gen equality cannot prove freshness) ⇒ a revoke could delete a slot the next test legitimately owns. — Mitigation: INV-DERIV-6, `cap::derivation_snapshot_reset()` in `test_isolate` **before** `restore_pool_data`, merged as a prerequisite (step 17 order); serial+gen matching then holds by construction on a freshly reset table.
- **[S1] Dangling `CNode*` / stack-CNode over-pin.** Tests build CNodes on the stack, so any stored pointer or retained reference is a use-after-free or a spurious `dispose()`. — Mitigation: INV-DERIV-2 (value-only edges; pointers obtained via `cap::lookup` during the walk, released on every path through the single 8f epilogue).
- **[S1] Double free / live-child leak in the retype rollback (r2).** A third failure point (`record`) sits inside `untyped.cpp`'s install window, and r1's "verbatim" reuse left `idx_child` installed. — Mitigation: step 9 — hoisted `idx_child`, `remove` of **both** slots before the creator releases, region ownership unchanged (prefix freed once via `target`, remainder once via `child`), verified by `cap_retype_record_full_rollback` with delta 0 and an explicit "no live child Untyped" probe.
- **[S2] Wrong-success on a recycled named slot (r2, resolves S2-2).** A lock-free slot read could validate a handle whose slot was recycled before the walk ⇒ no `take_child` match ⇒ `OK`/`0` for a handle the caller no longer owns (INV-MK-9 `:81`). — Mitigation: **INV-DERIV-10** — validate+pin under `cspace->lock_`, walk on the captured gen, destroy via gen-checked `remove_if`, re-verify after the walk and return `CAP_ERR_BAD_HANDLE` on any change; `cap_revoke_stale_named_slot_fails_closed` covers the deterministic half.
- **[S2] Deleting a foreign cap after a mid-walk recycle.** Between `take_child` and the destroy, the child slot's owner could `CAP_DELETE` it and install a different cap; a plain `remove(idx)` would delete that unrelated cap. — Mitigation: every walk-side destroy goes through `CNode::remove_if(idx, gen)` (steps 5/8d); a gen mismatch means "already gone", not an error.
- **[S2] Silent untracked derivation (deny-never-degrade).** A destination CNode that is not a capability of the source records nothing. — Mitigation: the boundary is explicit in the doc-block and outside the user-visible syscall contract (every syscall grant/copy/mint names a CNode cap of the caller); table-full and depth-exceeded **fail the operation closed** with a typed `CapError` and a rolled-back install, never a silent partial.
- **[S2] Lock-order or lock-window regression.** — Mitigation: INV-DERIV-1 (never both locks; `derivation_lock_` is `Leaf`, so any future nesting reports through the M2 §6.2 check; `record` after install-return, `forget_slot`/`remove_if` after the slot critical section and before `release()`); the auditor should confirm no new nesting at the three call sites.
- **[S3] `SYS_MAX` bump (86 → 99)** changes a libc-visible constant while closing a pre-existing drift. No test pins 86 (`test_syscall.cpp:1052` asserts `> 79`); the stub generator excludes `SYS_MAX` (`tools/gen_syscall_stubs.py:49-51`). Flagged for the audit's ABI checklist.
- **[S3] `sizeof(CNode)` growth** (+4 B `serial_`) could cross a MemPool class boundary. — Mitigation: `static_assert(sizeof(CNode) <= kMemPoolMaxBlockSize)` in `cap.cpp`; no `CSlot` growth (the edge table is out-of-line).
- **[S3] Derivation-table availability.** A shared 256-entry table means a busy granter can make previously working grants fail (`CAP_ERR_DERIVATION_FULL`, fail-closed) — step 15 records the counter, the rationale and the F9/#562 re-home.

## OPEN QUESTIONS

- **Q1 (syscall number; decision recorded, owner may veto; unblocks nothing).** §3.3 leaves N1–N9 "TBD at API freeze" and §3.4 shows `MAX_SYSCALL = 98` already accounts for every existing number, so no retired number is free. - **Q2 (§4.3 wording — r2: the contract is implemented, so this is NOT an implementation blocker; only spec wording is owner-gated).** §4.3 (`:252-253`) reads: revocation depth bounded `TBD at API freeze`; a revoke that exceeds the bound returns a typed error and is resumable. **r2 implements both clauses**: depth is bounded at *creation* (`CAP_ERR_DEPTH_EXCEEDED`, so no revoke can exceed it — strictly stronger), and every revoke is bounded per call (`kRevokeEdgeBudget`) with typed `CAP_ERR_REVOKE_INCOMPLETE` + resume-by-re-invocation. Implementation therefore proceeds; the only open point is spec wording, resolved by the step-16 follow-up. **Exact owner question:** "May §4.3 state (a) depth bounded at creation by `CONFIG_CAP_MAX_DEPTH = 8` with `CAP_ERR_DEPTH_EXCEEDED` on the creating op, and (b) the revoke-time typed-error/resume clause satisfied by a per-call edge budget `kRevokeEdgeBudget = 64` + `CAP_ERR_REVOKE_INCOMPLETE` — or does the owner require the bound to apply to revoke-time *depth* instead?" If the owner chooses revoke-time depth, the delta is confined to step 7 (drop the creation-time `child_depth` rejection), step 8e (stack overflow becomes `CAP_ERR_REVOKE_INCOMPLETE` instead of the unreachable hard error) and the first half of the depth test; that variant must be re-planned, not patched in, because it widens the S1 profile (deep chains, deeper stack).
- **Q3 (scope note, non-blocking).** The bounds live as `kCapMaxDerivations`/`kRevokeEdgeBudget` in `cap/derivation.hpp` instead of `nexios_config.h`, because `nexios_config.h` is owned by M4/F9 (#563/#562). If F9 wants them configurable it is a one-line move; no code depends on the location.
- **Q4 (non-blocking, tunable).** `kRevokeEdgeBudget = 64` is a new unmeasured number (like `kCapMaxDerivations`, it has no Q7 row). Rationale: 8× the maximum depth chain, worst case 16 384 comparisons per call, ≤ ⌈256/64⌉ = 4 calls for a saturated table. The owner may re-pick at the spec follow-up; nothing depends on the exact value.
- **Q5 (non-blocking, folded into step 16).** The typed error is **not** visible to userspace: the syscall face stays `SYS_ERR_GENERIC_FAIL` per the frozen T-1/Q3 contract, so "resumable" is expressed as "call again until it returns 0".
