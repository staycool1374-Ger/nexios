## (a) TTBR1 programming cannot corrupt the shared root — PASS

- `vectors.S:irq_context_switch_common`: on a published `scheduler_load_cr3_from` (non-zero) it programs
  TTBR0 verbatim then `ubfx x5, x3, #0, #48` (≈ `& 0x0000FFFFFFFFFFFF`) into TTBR1. Mask equals the
  `kPhys48Mask` used by `switch_address_space` — strips exactly the ASID field (bits [63:48]).
- ASID-strip is safe: `TCR_EL1 = 0x5B1103510` (boot.S:295) has bit 22 (A1) == 0, so TTBR0's ASID (0 for
  kernel/harness tasks) applies to both halves; the TTBR1 ASID field is ignored by hardware, and
  `read_ttbr1_el1()` consumers (`dump.cpp`, `interrupt_controller.cpp`, `page_table_impl.hpp`) expect a
  clean physical root. Stripping is therefore both required and harmless.
- TLBI coverage: both MSRs precede the existing `dsb sy; tlbi vmalle1; dsb sy` with the shared `isb` at
  `.tls_apply` as the pairing point. The full `vmalle1` is the isolation barrier (global `nG=0` leaves must
  never alias across tasks) — the patch correctly does NOT attempt targeted-TLBI/ASID optimisation, and
  memory.md §7.1.2 rule 4 defers that until private-window leaves become `nG=1`.
- No foreign-root switch: the epilogue only ever installs the scheduler-published root of the task being
  resumed; `cbz x3` (no publish) leaves both TTBRs untouched, which is correct because no switch was armed.
  `arch::switch_address_space` has exactly one caller (`elf.cpp:959`, the task's own new root).
  Temporary peer user-half switches (`syscall_handlers_misc/thread.cpp`, `scheduler_lifecycle.cpp:409/421`,
  `test_waitpid.cpp`) still use `write_cr3` (TTBR0-only) — exactly what the §7.1.2 rule 2 contract demands.
- Scratch-register safety: x5 is stored by `save_all` (vectors.S:136) before use and reloaded by
  `restore_all` (line 165); x3/x4 are reloaded via `adrp` after the `bl scheduler_on_context_switch`
  clobber window. Safe.
- Pre-existing `arch_page_table_activate()` (TTBR1 write + dsb/isb, no TLBI) is untouched by this patch and
  has no production callers on aarch64 (only the `ArchPageTable::activate` wrapper, itself uncalled outside
  tests); the "no TTBR1 write outside a TLBI window" rule governs the switch paths this patch owns.

## (b) exec retarget-before-free ordering — PASS (prior UAF fixed)

- Old code: `if (read_cr3() != new) write_cr3(new)` — TTBR0-only, guarded. The kernel kept executing with
  TTBR1 pointing at the OLD root across `free_user_pages(old) + free_page(old)`: use-after-free of the old
  root's kernel half.
- New code (`elf.cpp:959`): unconditional `arch::switch_address_space(new_pml4)` BEFORE
  `install_segment_canaries` (correct: canaries armed in the new AS) and BEFORE the old-root free
  (lines 964–967). Unconditionality is the fix, not a waste: a stale TTBR1 must be retargeted even when
  TTBR0 already names the new root.
- Ordering inside `switch_address_space` (TTBR1 first, then TTBR0 via `write_cr3` which supplies
  dsb/tlbi_alle1/dsb/isb) is the safe direction: at no instant does either half point at a freed root.
  The transient mixed-root window (new kernel / old user) is benign — the new kernel half is a superset
  clone and interrupt handlers do not touch the private window. No locks are taken/needed; same context
  and barrier shape as the pre-existing `write_cr3` path.

## (c) HHDM rewind: no leak / double-free, exact pre-test mapping — PASS

- Save side (aarch64 arm): saves L0[256]→L1 whole + child L2s for slots {0,1,256} (MMIO alias, RAM window,
  upper HHDM) = 4 pages, sized symbolically via `HHDM_PD_BYTES` through the `off_*` chain
  (`off_hhdm_pd`/`off_ident_pd` and all save/restore call sites key off the same constant — no hardcoded
  offsets to drift).
- Restore side: per-slot L1-descriptor equality gate (`saved_slot != live_slot` → log + skip, never blind
  memcpy) mirrors the x86 `0x5000`/`0x3000` fail-closed gates. L1 slots are immutable under `map_page`
  (splits happen at L2→L3, never replace L1 links), so the skip arm is unreachable defense-in-depth.
- Reclaim predicate — `(s == 0 || (s&3) == 1) && (c&3) == 3` → `free_page(c & mask)` — fires exactly for
  block/absent→table transitions, i.e. precisely the L3 page the test's split allocated (1:1 L2-entry→L3
  mapping, no double-free possible; table links carry no UXN/PXN so `& 0xFFFFFFFFF000` is exact).
  Table→table remaps allocate nothing (nothing to free); `memcpy` of the saved L2 then restores the exact
  pre-test entries. `tlb_flush_all + isb` follows the loop. The saved-table/live-zero case (test unmapped)
  correctly skips the free and restores the entry — same shape as the long-shipped x86 predicate.
- x86 HHDM save/restore bodies are byte-identical to the parent (only the `#if` line and comments changed).

## (d) Boot-stack move + fail-stop cannot brick boot — PASS (fail-closed)

- `_boot_stack` (+ `_boot_stack_end`) moved from `.boot.data` to `.boot_stack`; boot.S is the sole producer
  of `.boot.data`/`.boot_stack` input sections on aarch64, so nothing else shifts. The `.boot_stack`
  output section keeps its `:boot_data` PHDR, ALIGN(4K) placement before `boot_vma_end`, and the
  higher-half `_stack_start/_stack_end` aliases — `is_boot_stack_rsp()` and
  `integrity_stack_markers_span` now bracket the live stack by construction.
- Fail-stop (`boot.S:105–114`): `span = _stack_end_low − _stack_start_low; if (span < 16384) park`.
  `b.hs` (unsigned ≥) falls through for any healthy layout (16 KiB stack alone saturates the threshold).
  The park arm (`daifset; wfi; b`) is fail-CLOSED: it can only trigger on a future linker regression that
  re-empties the span, in which case halting loudly is correct (booting with a corrupt boot-stack span
  would defeat the integrity span test). Unbounded-loop style rule exception applies — boot-time,
  pre-scheduler fail-stop halt, same as the riscv64 precedent cited in the comment.
- `ldr x0, =_boot_stack_end` (line 96) still resolves to a low-VMA PA pre-MMU (the symbol moved WITH the
  section, still below `boot_vma_end`). Post-MMU `sp += HHDM_OFFSET` conversion (line 333) unaffected.

## (e) x86/riscv64 paths — PASS with one noted (safe-direction) deviation

- x86_64: HHDM save/restore bodies byte-identical; only the `#if` narrowed from `X86||AARCH64` to `X86`
  (the aarch64 logic moved to its own arm) plus comments. `switch_address_space` shims on x86/riscv are
  pure `write_cr3` aliases — zero behavioural delta; cross-arch parity (§9/CODING_STYLE §1) holds.
- riscv64 deviation (auditor-flagged, accepted): the identity-PD restore gains the previously-missing
  `#if X86||AARCH64` gate. In the parent it was UNGATED despite the "#152 same 4-level gate" comment —
  i.e. the comment already claimed a gate that did not exist. On riscv the old code could only silent-skip
  (`pd_phys == 0x3000` essentially unreachable under the Sv39 `(pte>>10)<<12` decode, with a pathological
  fault risk from the `& ~0xFFF` misdecode); the new code skips cleanly at compile time. The
  `identity_modified_` flag can still be armed on riscv (`vmm_map.cpp:116,391`, `vmm.cpp:470`) but is then
  simply never consumed there — dead state, no functional effect; the Sv39 HHDM L1 restore below is
  untouched. This completes the documented intent in the fail-safe direction. The "byte-identical" summary
  line should have said "behaviour-identical (one latent-misdecode gate completed)" — doc nit only.

## (f) No new IRQ/lock hazards — PASS

- No spinlocks, IRQ masks, or scheduler publish slots added. `vectors.S` TTBR writes execute under DAIF
  (trap entry, pre-existing). `switch_address_space` inherits the `write_cr3` barrier envelope. The
  `test_no_dynamic_alloc_after_init.cpp` change is test-only and keeps the existing `IrqGuard` around the
  warm-up split; the per-arch `split_now` predicate (`(e&3)==1` on aarch64 vs PS-bit on x86) is
  descriptor-correct — bit 7 is AP[1], an address-lottery bit in a block descriptor — with an accurate
  doc-block update (systemically-wrong-test ritual followed).

## Observations (non-blocking, no action required for this issue)

1. memory.md §7.1.2 rule 1 says both TTBR writes sit "inside" the `dsb/tlbi/dsb window`; strictly they
   precede it (MSR,MSR → dsb → tlbi → dsb → … → isb). Functionally covered (program-ordered MSRs, full
   flush, trailing isb before `eret`; both roots live at that instant). Suggest rewording to "ahead of"
   at the next spec touch.
2. `constexpr uint64_t kSlots[]` uses a `k`-prefix outside the `SCREAMING_SNAKE` convention — warning-class
   only (Errors: 0 confirmed), consistent with neighbouring test-harness style.
3. `test_isolate.cpp` uses `reinterpret_cast` throughout (pre-existing file-local idiom); unchanged by
   this patch.
4. Fix-summary wording "x86/riscv64 paths byte-identical" overstates (e)-above; behaviour-identical with
   one fail-safe gate completion. Recommend precise wording in future summaries.
