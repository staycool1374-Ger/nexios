### [S1] — none

All safety-critical properties hold:

1. `vmm.cpp:365-541` — `map_page_try` is a line-faithful split of the old
   `map_page` body. Every silent-drop site now returns
   `errors::VMM_ERR_PAGE_ALLOC` (riscv64: l1/split/l2; x86/aarch64:
   pdpt/pd/split/pt — 7 sites total across arches) and both arch branch ends
   return `VMM_ERR_OK`. The void `map_page` wrapper (`vmm.cpp:547-549`)
   discards the code, so legacy behavior (one-time log + drop) is
   bit-identical. No mapping-semantics change on any arch.
2. `vmm.cpp:1851-1856` — `map_page_err` now returns `map_page_try(...)`
   instead of unconditionally returning OK after a void call. Genuine
   propagation; the prior shape silently confirmed failed maps (§5:
   reachable exhaustion must return a code).
3. `elf.cpp:270-283,355-365,377-387` — suffix-only free on mid-load OOM is
   correct: the mapped prefix consists of user-owned pages reclaimed by the
   caller teardown `free_user_pages(pml4)` (`elf.cpp:562-564`), and the
   never-mapped suffix pages are freed inline. No double-free (suffix addrs
   are absent from the tables the teardown walks), no leak (prefix + tables
   freed by teardown, suffix freed inline). Stack/heap pass
   `executable=false`, preserving VULN-H1 NX.
4. `elf_loader.cpp:630-645,664-678,697-707,1560-1567` — every new `_err`
   failure path frees the orphan page(s) and runs the pre-existing teardown
   (`fail_fresh_build_locked` = `unmap_fresh_golden_locked` +
   `free_user_pages` + `free_page(pml4)`, `elf_loader.cpp:480-488`;
   `cleanup_and_idle` frees `pml4_`, `elf_loader.cpp:1338-1342`). The pin-loop
   read-back replacement frees `wp` before the identical fail sequence — same
   state as before, minus the TOCTOU read-back. Lock discipline preserved
   (`IrqGuard` + `lock_` around the locked teardown, matching adjacent
   OOM paths).
5. `pager_registry.cpp:662-733` — `phase2_ok` gating is sound: pins are only
   acquired in the phase-3 commit loop (`fc->acquire()`,
   `pager_registry.cpp:692`), so a phase-2 OOM holds zero pins and the
   existing `!committed` path (PTE rollback over `count` + `-1`) is the
   correct join. Rollback over unmapped suffix entries resolves to walk-only
   misses (no-ops); NX preserved (`executable=false` passed explicitly).
6. `pmm.cpp:176-198` — `rebuild_free_list()` resetting `pool_free_head_`
   matches the documented contract (`pmm.hpp:324-328`: both heads re-synced
   from the bitmap). The old code rebuilt list contents while leaving a
   potentially stale pool head linked, which can serve already-allocated
   pages (double-allocate of table pages). Fix is 6 lines, `noexcept`,
   allocation-free, loop-bounded. Production-relevant and correct.
7. Infallibility docs (`vmm.hpp:49-51,82-84,232-234`) verified against
   implementation: `init` (`vmm.cpp:55-119`) is allocation-free zeroing of

   `create=false` (only alignment can fail); `free_user_pages`
   (`vmm.cpp:1369+`) walks with `create=false` and frees. Honest contracts.
8. `map_page_in_pml4_err` defaulted 5th param (`vmm.hpp:205-208`,
   `vmm.cpp:1900-1908`): default `executable=true` reproduces the old 4-arg
   `_err` body (`..., user, true, pml4_phys`) exactly, so all pre-existing

1. `src/kernel/elf/elf_loader.cpp:631-634,665-667` + patch-summary precision
   — the `try_rerun` stack/heap rebuilds call the 4-arg `_err` form, i.e.
   `executable=true` (executable stack/heap), while `elf.cpp:356-364,
   378-386` passes `executable=false`. This inconsistency is **pre-existing**
   (the old code used the 4-arg void form, `vmm.cpp:694-698`, which hardcodes
   `executable=true`) and the patch is behavior-preserving, so it is not a
   regression. But the patch summary's "stack/heap pass `executable=false`"
   claim holds only for `elf.cpp`, and the residual executable-stack/heap in
   the rebuild path (VULN-H1 surface) survives this subitem. Rule: honest
   W^X posture per mapping site. Recommendation: follow-up issue to pass
   `executable=false` in the two rebuild loops (and audit the pin/async
   sites, which also inherit legacy-executable).
2. `src/kernel/test/test_page_tables.cpp:20-26` — duplicate
   `#include <scope_guard.hpp>` (lines 20 and 26). Cosmetic; style-check
   clean per validation, but one include should go.

   differs (`rebuild_free_list()` before `IrqGuard` in the former, under

   unify the order in a follow-up for doctrine consistency.

   non-W^X option (`executable=true`). Justified here (legacy preservation,

   eligibility (continuation of S3.1).
