### Critical checks (re-run on the full patch)

1. **Committed-pin exactly-once release across {drain_task, unregister, invalidate_cap, snapshot_reset}** — VERIFIED. Every path removes table entries **under** `s_lock_` and releases pins **outside** it (`release_committed`/`release_all_committed`, `pin->release() → dispose → invalidate_cap → s_lock_` is safe because the lock is never held at that point). An entry is removed from the table before its pin is released, so no two paths can collect the same entry → no double-release; slot `state=FREE`/`mapped_count=0` prevents re-collection → no leak. The only pin release executed while holding `s_lock_` is `map()` phase-3's acquire-failure rollback — **unreachable in production**: phase 3 runs under `IrqGuard` (IF=0, no concurrent revoke), the `!fc->revoked()` gate precedes every `acquire()`, and even in a hypothetical direct-call misuse the refcount is ≥2 (CSpace slot ref + the `cap::lookup` ref released only after `map()` returns), so `dispose()` cannot fire under the lock. Runtime confirms: roundtrip's committed pins release on client death (no PMM/pager-map delta).
2. **ISR-context lock safety** — VERIFIED. `delegate_fault` uses `s_lock_.try_lock()` and fails **closed** (SIGSEGV via the normal signal path) when the lock is held; every reject path (`F8` pager==client, dead pager, `F9` poison, `F10` canary, `B1` pending) explicitly `unlock()`s before returning; the success path unlocks before the notify pulse and the block. `watchdog_scan` uses `try_lock` and safely skips the tick on contention. No blocking `s_lock_` acquisition exists in any ISR-reachable path. Lock order `scheduler_lock_ → s_lock_` holds (no task path takes `scheduler_lock_` while holding `s_lock_`; `dequeue_ready`/`set_task_ready`/`find_task` are lock-free; `Notify::wait` releases its lock before `reschedule` — notify.cpp:115-119 — so the ISR-side `notify()` never spins on a preempted holder).
3. **`map()` fully under `IrqGuard`** — VERIFIED. The guard spans phase 1 (claim) + phase 2 (VMM map) + phase 3 (revalidate + commit) + the wake. No tick → no deferred switch → no client termination / watchdog / abort / unregister interleave mid-map (F6 closed). Nested `IrqGuard` inside `set_task_ready` is safe (HAL guard restores the saved `irq_was_`; an inner destructor never re-enables what the outer guard disabled).
4. **Exactly-once resume (PENDING→consumed gate)** — VERIFIED. Consumers are exactly {`map` phase-3, `abort`, `watchdog_scan`, `drain_task`, `unregister`, `snapshot_reset`}, all under `s_lock_`; the first consumer flips `pending=false` so the rest cannot match. Late `MAP` after a consume fails phase-1 (`!sl.pending`) with `-1` and no wake — no double wake. `drain_task`'s multiple `wake_client` calls for one client are benign: `TaskQueue::push_back` refuses a second enqueue via `in_ready_queue_` (task_queue.cpp:15-16).
5. **Classification F1-F10 / count / unregister authority** — VERIFIED. F2 (recover-IP), F3 (P), F4 (RSVD), F5 (U/S), F6 (I/D), F7 (CR2≥USER_SPACE_LIMIT) all reject **before** the lock and before the block path; F8/F9/F10/B1 reject under `try_lock` with explicit unlock. `map()` rejects `count > fc->count` before any VMM work (F4). `unregister(caller, client_pid)` requires `caller.id == client_pid` or `sl.pager_id/gen == caller` (F3); third-party eviction rejected.

### S3 notes (non-blocking, no change demanded)

1. `invalidate_cap`'s multi-entry while-loop is statically verified but not directly runtime-driven (the revoke test revokes before any map; the roundtrip exercises the multi-entry shape via `drain_task`). Coverage gap only.
2. `map()` phase-3's acquire-failure rollback releases pins while holding `s_lock_`. Unreachable today (IrqGuard + `!fc->revoked()` gate + refcount ≥ 2), but fragile by construction; a future non-syscall caller that passes a cap whose only references are the pins would deadlock in `dispose → invalidate_cap`. Hardening: collect and release the rolled-back pins outside the lock.
3. `map()` does not validate `fc->is_user`; a FrameCap wrapping a kernel-owned frame would trip the unconditional `PMM::is_user_page` panic inside `map_page_in_pml4` (fail-stop, not silent). Not reachable via capability mediation (user tasks only obtain user frames). Hardening: reject non-user caps at `map()` with `-1`.
4. `PagerFault` still carries vestigial `mapped_va[]/pin[]/mapped_count` fields (the committed table lives on the `Slot`). Dead code, harmless.

## PATCH

**Verified-correct elements of the patch (beyond the N1/N2 remediation):**

1. **Committed-pin lifecycle:** pins acquired in `map()` phase 3; every release path (drain_task/unregister/invalidate_cap/snapshot_reset) collects under `s_lock_` and releases/wakes/unmaps outside it; `drain_task` runs before `free_user_pages` and before the pager's `Notify` destructor; `FrameCap::dispose()/revoke()` both call `invalidate_cap`.
2. **ISR lock discipline:** `delegate_fault` `try_lock` + fail-closed SIGSEGV; `watchdog_scan` `try_lock` + skip-tick; lock order `scheduler_lock_ → s_lock_` holds everywhere.
3. **`map()` IrqGuard atomicity:** guard spans phases 1-3 + the wake; nested `IrqGuard` with `set_task_ready` is safe; `abort()`/`watchdog`/`drain`/`unregister` cannot interleave a mid-map pager; `watchdog_scan` additionally defers `map_in_progress` records.
4. **Exactly-once resume:** single atomic PENDING→consumed gate; consumers enumerated above; late MAP fails with `-1`; `wake_client` revalidates id+generation and is idempotent via `in_ready_queue_`.
5. **Classification F1-F10:** F2-F7 reject before the lock; F8/F9/F10/B1 under `try_lock` with explicit unlock; every reject precedes the block path (BLOCKED + `dequeue_ready` + `switch_away_from_terminating`).
6. **Cross-AS map authority:** fault-record-gated; `cap::lookup(Frame, WRITE)` in the pager's CSpace (balanced reference); NX-only; `count <= fc->count`.
7. **Syscall table integrity:** 69-73 with `MAX_SYSCALL=74`, exactly 74 handlers; none in `k_syscall_fast[]`; RECV validates the destination before consuming.
8. **Watchdog:** `deadline_tick = ticks + 1000`; per-fault fail-closed (registration KEPT, VA poison latch F9); eviction only on pager death/unregister; mid-map records deferred.
9. **Cleanup/exec ordering (check 7)** and **test honesty (check 10)** confirmed at runtime this session.
