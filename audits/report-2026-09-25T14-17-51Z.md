## FINDINGS
- [S1] docs/specs/debugd.md:§2 (spec L71) vs §4 (spec L118) — normative syscall-count contradiction: §2 states "exactly four debug syscalls" while §4 offers "a fifth syscall, sys_task_debug_attach" as an equal implementation branch.
  WHY: One permitted implementation exceeds the normative count, so the count cannot hold under both branches.
- [S1] docs/specs/debugd.md:§10 (spec L248) vs §3 (spec L89)/§4 (spec L128) — fail-safe asserts a parked target "holds no locks the scheduler needs" while §3 parks running targets on first register access and §4 defines no safe-point or deferred-stop rule.
  WHY: A target stopped mid-syscall or mid-IPC-wait can hold IPC queue state or kernel-side resources, making unconditional resume/terminate unsound without a stop-boundary plus reaper rule.
- [S2] docs/specs/debugd.md:§3 (spec L81) + §4 (spec L118) — no rule mints or grants the initial target_cap, yet attach consumes a handle rather than a pid.
  WHY: A debugger cannot attach to a running daemon it was never granted a handle for, leaving the primary attach path unimplementable as specified.
- [S2] docs/specs/debugd.md:§4 (spec L124) — drop-oldest stop-event overflow can discard task-death W/X events that the same section requires reported.
  WHY: Losing the death event leaves the debugger believing a reaped target is still stopped, contradicting the no-orphaned-parked-task guarantee.
- [S2] docs/specs/debugd.md:§3 (spec L109) vs §10 (spec L250) — ABI v1 freeze of the debug slots versus release-build ENOSYS on the same numbers.
  WHY: One ABI version cannot both freeze slot behavior and make it build-dependent without an explicit debug-only carve-out.
- [S2] docs/specs/debugd.md:§7 (spec L185) vs §5 (spec L151) — Logger output multiplexed onto the RSP byte stream breaks the exact $data#cs framing/checksum discipline.
  WHY: Interleaved Logger bytes invalidate GDB checksums, so the transport cannot satisfy both requirements without a dedicated stream or a muted Logger.
- [S2] docs/specs/debugd.md:§2 (spec L74) — claims "§10 defines the semantics" of kernel panic while a task is stopped, but §10 contains no panic path.
  WHY: The QEMU-GDB-freezes-all-CPUs coexistence case has no defined disposition for parked-task and stop-queue state.
- [S2] docs/specs/debugd.md:§10 (spec L253) — watchdog suspension for stopped targets has no resume-realignment or supervisor-visibility rule.
  WHY: Without defining whether stopped time is back-charged, resume can spuriously trip or silently mask supervision.
- [S3] docs/specs/debugd.md:§4 (spec L134) vs §6 (spec L171) — breakpoint shadow truth owned by both kernel and controller with no source-of-truth rule.
  WHY: Overlapping breakpoints and detach-restore need one authoritative owner when the two tables disagree.
- [S3] docs/specs/debugd.md:§9 (spec L235) — task-info block read is not bound to any §3/§4 call.
  WHY: A new kernel read surface is introduced without assigning it to a defined syscall, leaving it unverifiable per §11.
