## INVARIANTS & CONCURRENCY BOUNDARIES
- INV-MK-4 (docs/specs/microkernel-transition.md:77): task context runs with IF==1 except inside an explicit `IrqGuard`. Combined with the gate's own bit 2 (`irq_guard_depth_own()==0`), "IF==1 + no own IrqGuard depth" *proves* task context — that proof is what bit 4 may consume.
- The IsrContext predicate is one definition now: `nesting != 0 && !in_syscall_trap_level() && !interrupts_enabled()`. Fail-closed direction preserved: IF==0 always denies, on every arch, with or without a stale count.
- `entry_if` stays a **single sample** per `reschedule()` call: bit 4, bit 5 and the post-park IF restore all consume the value captured at `scheduler_tick.cpp:1477`, before any guard. No hlt/switch/blocking point exists between the sample and the gate, so the sample is the live IF value; an intervening ISR restores IF on return.
- Orthogonality: bits 2 (IrqGuard depth), 3 (held spinlock), 9-13 (task validity / single-task / idle / harness / impersonation) are untouched. A stale count can never widen them.
- `resched_park_gate_task()` remains the only place that decides parkability of the *task*, and still requires `state == BLOCKED` + valid magic + (test mode) RSP-inside-TCB — the fix cannot park a RUNNING or foreign TCB.
- Park body (`resched_park_until_dispatched`) is unchanged: `sti/hlt/cli` loop, exits on `state != BLOCKED` / `current != &t` / bad magic, restores entry IF. No lock, no allocation, no ready-queue touch, bounded by the tick (#545 INV-L2/-W1' invariants hold unchanged).
- Concurrency boundary: `resched_park_gate_base()` runs **outside** any IrqGuard (CPU-local, scheduler state read only through `Scheduler::current_task()`); `resched_park_gate_task()` runs **inside** the arm's `arch::IrqGuard` (IRQ-off makes `all_tasks_.size()`/current reads stable). The helper is called only from the pre-guard side, so it never observes a half-taken guard.
- No dynamic allocation, no printf, no new global, no DEBUG/release control-flow divergence (the predicate is computed identically in both builds; only the existing telemetry counters stay `CONFIG_DEBUG`-gated).
- Cross-arch parity: one arch-neutral header predicate; no `#if defined(CONFIG_ARCH_*)` anywhere in the change. x86_64/aarch64 behavior is bit-identical (their task-context nesting is 0, so bit 4 never fired anyway); riscv64 is the only arch whose verdict moves — and it moves toward the already-audited lock-park verdict.

## SIL 3 / SAFETY RISKS
- [S1] The IF==1 carve-out admits a park in *any* IF==1 context; a hardware ISR that re-enabled interrupts and then reached `reschedule()` would hlt inside the ISR and stall the interrupted frame (the #582 r2 S1 conviction class) — Mitigation: the helper keeps `!in_syscall_trap_level()` and the IF conjunct; step 1 documents the per-arch proof that trap entry clears IF; the hardware-IRQ delivery path is statically enumerated this session — every `arch::sti()` in `src/kernel` is in a syscall handler wait-loop, an ipc wait-loop, the park body itself, `irq_spinlock_guard`/`IrqGuard` restore, or a task entry, i.e. either trap-level or task context; no IRQ-delivery handler calls `reschedule()` (the three `kernel.cpp` sites are exception/syscall vectors). The coder must re-run that enumeration (`rg -n 'arch::sti\(\)' src/kernel`) and paste it into the audit evidence.
- [S1] Predicate re-fork: fixing bit 4 by copying the expression (instead of the shared helper) guarantees the next divergence, which is the defect class being fixed — Mitigation: single `arch::isr_context_park_denied()` in `irq_guard.hpp`, both gates call it; the auditor must reject any inline duplicate.
- [S2] Telemetry semantics shift: `resched_park_denied_why()` bit 4 (`0x10`) stops appearing in task context on rv64, so any QE reading that bit as "stale nesting detected" loses its tripwire — Mitigation: docs (step 8) plus the issue comment; the exhaustion dump already prints the whole bitmap, and `g_depth_sat` remains the arch-side diagnostic for the underlying unbalanced counter.
- [S2] More real parks on rv64 change per-test timing (hlt-wait instead of arm-only return) in a class already sensitive to TCG stalls — Mitigation: riscv64 400 s/1200 s policy timeouts, a control run on an unmodified worktree if anything fails, and the 3-attempt circuit breaker; no test edits to "fix" timing.
- [S2] Sample-vs-live IF skew if a future caller moves `resched_park_gate_base()` after the IrqGuard take — Mitigation: the helper takes the IF value as a parameter (cannot silently re-read), the comment at the call site states "pre-guard, single sample", and `entry_if` is shared with bit 5 so a move would break bit 5 visibly.
- [S3] `irq_guard.hpp` is widely included; a new inline must not add dependencies or ODR surface — Mitigation: header-only inline using already-included symbols; no new extern, no new storage.
- [S3] rv64 stale-nesting root cause (unbalanced increments; candidates: abandoned trap frames on switch-apply and `.Ltrap_park` never decrementing, `syscall_entry.S:462-478`) is NOT fixed here and stays live as a latent count skew for every other nesting reader (`kernel.cpp`, `dump.cpp`, `scheduler_switch.cpp:1160`) — Mitigation: state it explicitly in the issue/LEARNINGS entry and file a separate follow-up (owner decision) rather than folding an arch-asm balance fix into a predicate change.
