## INVARIANTS & CONCURRENCY BOUNDARIES

**INV-T1 — kernel tick-only contract (normative, one table).**
STAYS in kernel: (1) tick *source* `arch::Timer` (APIC periodic x86 / CNTP aarch64 / SBI timer riscv64) and `Timer::ns_monotonic()`+ `raw_counter()` (hardware facts, rewind-proof); (2) `Scheduler::on_tick` core: EDF/deadline list, RMS dispatch, effective priority, sporadic **replenishment** (`process_replenishments`), deadline-miss detection; (3) the event-timer wheel **for kernel-internal waits only** — `ipc.cpp` bounded receive (#18), `irq_delivery.cpp` wait timeout, `tick_watchdog`, `send_sync_bounded` guard; (4) #190 timeout faults / budget enforcement (future, same seam); (5) admission (Liu-Leyland) + quantum; (6) *relay* primitives — `IPC::send`/`recv`, server-death wake of blocked clients (#545 M1), dead-owner tombstones (#241); (7) `PdRole`/`SDF` composition and supervision/restart.
MOVES to timer-srv: nanosleep arming + blocking, CLOCK_REALTIME anchor + arithmetic, TIMER_CREATE/SETTIME/GETTIME/DELETE registry, TIMERFD_CREATE/SETTIME expiry counters + readiness, per-tick POSIX wake re-apply (`PosixTime::reapply_wakes` — stubbed no-op under ON per INV-T3), `SYS_GETTOD` wall value.
STAYS in kernel (decided, not overlooked): syscall 33 ALARM (`sys_alarm`, `alarm_ticks`/`alarm_armed`, tick countdown + `sleep_armed`-only wake at `scheduler_tick.cpp:841-855`). Per-task tick-counter signal delivery is kernel-internal; only `TIMER_CREATE`-family registries move. The ALARM sleeper-wake leg at `:851-853` goes dead under ON (no sleeper sets `sleep_armed` there anymore) — no MOVES design for 33 in this lane.
Explicitly NOT moved: the wheel itself, the tick source, and the *relay* receive. A reviewer must be able to answer "where is the deadline stored?" with **timer-srv user memory only**.

**INV-T2 — no kernel POSIX deadline state in the ON leg.** No `PosixTime::*` timer/sleep/timerfd slot may be reachable when `CONFIG_TIMER_SRV=1`; the ON path must not call `TimerWheel::arm` for any 80–83 op (grep-verifiable: the ON leg's only `arm()` callers are `ipc.cpp`, `irq_delivery.cpp`, `tick_watchdog`).

**INV-T3 — zero scheduler surface (the #600 fence).** This lane edits `scheduler_tick.cpp`, `scheduler_queue.cpp`, `scheduler_debug.cpp`, `ready_queue_manager.cpp` **not at all**. The wake model is chosen so no tick hook is needed: the server blocks in `ipc_recv_timeout` (an existing kernel-internal bounded receive; the same bounded-receive primitive `watchdogd` exercises at `userspace/watchdogd.c:207-210` via its raw `__syscall5` + `r != msg.type` check — citation corrected, not the `ipc_recv_timeout` wrapper which only `timer-srv.c`/`bind-verify.c` use). Concretely: `PosixTime::reapply_wakes` is stubbed to a no-op under `CONFIG_TIMER_SRV=1` (lives in `time/posix_time.cpp`, NOT a fenced file — no fence breach); the `scheduler_tick.cpp:550-573` per-tick `sleep_armed`/`sleep_expired` scan stays in the tree but provably finds nothing under ON (no sleeper ever sets `sleep_armed` — park happens in `IPC::recv`, and the scan is bounded reads only; measured idle cost posted with the gates). Deadline wake = wheel expiry + message wake, exactly as today. If a later increment wants a per-tick broadcast it must be a separate issue that rebases on #600 — it is NOT part of #194.

**INV-T4 — server time is monotone by construction.** The server must never read `arch::Timer::ticks()` (harness-rewound via `set_ticks_for_test`, `hal/timer.hpp:104`; `snapshot_restore` rewinds it) and never accumulate pulses. It samples `CLOCK_MONOTONIC` (kernel `ns_monotonic`, rewind-proof) and keeps its **own** latch: `now = max(sample, g_last_ns)`; a backward sample holds the latch and increments `g_rewind_events` (never acts on it). Deadlines are absolute in the server's own ns domain; every add is saturating (`#349`).

**INV-T5 — cancellation exactness.** Every server-issued client event carries `token = (owner_id, owner_gen, slot, slot_gen, server_epoch)`. The kernel drops any event whose token does not match the live fd/slot registration *before* waking anybody; a freed slot bumps `slot_gen`; a restart bumps `server_epoch` and the server purges all slots on an epoch increase. "No stray fire after `timer_delete`" is therefore a drop-side guarantee, not a race to win. Drop-site mechanics (enforceable, no kernel slot table — INV-T2 holds): the vnode for a timerfd carries the server-issued `(slot, slot_gen)` **opaquely in its tag** at create time (never interpreted by VFS, never a kernel deadline table); `timerfd_read_entry` gains an ON leg that compares the arriving event token against the vnode tag and drops mismatches before waking (stale slot reuse and post-delete in-flight events die here, not in a race); `timer_delete`/close frees the local registration first so any later event necessarily mismatches. Step 27's "slot freed locally" is consistent with INV-T2 because the tag is opaque VFS data, not deadline state.

**INV-T6 — restart/snapshot purge.** `daemon_mgr` restart → `on_restart(pid)` (exists) → epoch bump; `test_isolate` snapshot restore → `timer_srv::snapshot_reset()` (epoch bump + tombstone clear) so no pre-restore arm survives into a restored suite (mirrors `TimerWheel::snapshot_reset` generation discipline). The `test_isolate.cpp` call-site edit is explicitly QE-owned (test file on `testbed`; dev must not touch it) — INV-T6 has no implementer until QE wires it, and the dev lane ships with the hook unconnected but specified.

**INV-T7 — single decision point per op.** The ON/OFF choice is compile-time only (`#if CONFIG_TIMER_SRV`); no runtime "if server alive then X else Y" in a handler — a runtime fallback would let one call double-serve (double fire). Test-side branching on `timer_srv_alive()` stays (it is a skip, not a fallback).

**INV-T8 — every unbounded kernel wait has a documented waker (§11.3).** `nsleep_wait`/`timerfd_deliver` block with no kernel timer: the waker is (a) the server's expiry message, and (b) server death → the existing death-wake makes `IPC::recv` return, and the handler returns `-EINTR`/`-EAGAIN` (never a hang). Each block site: `state=BLOCKED` → `dequeue_ready` → `reschedule()` (§11.1/§11.2), lock released first.

**INV-T9 — lock ordering.** The proxy takes no spinlock across IPC (state is `__atomic` pid/epoch/anchor cells). `PosixTime::lock_` is OFF-leg only. Server-side state is single-threaded (one PD, one loop) — no lock at all, which is the point of the externalisation.

**INV-T10 — budget/admission unchanged.** timer-srv keeps SS(1,10,0) prio 20 (Liu-Leyland sum unchanged at 0.9, still informational per the briefing scheduler section — no gotcha number cited, the vault's #11 is exec-ns metering, not LL); do not raise it in this lane — the wake model above keeps idle cost at one bounded receive per deadline, not per tick. #190 owns donation/overrun.

**INV-T11 — cross-arch parity.** Identical wire + identical server source on all three arches; only the RTC *device* access differs (x86 CMOS ports, aarch64 PL031 MMIO, riscv goldfish MMIO, riscv-without-goldfish ⇒ `RTC_NEVER` degrade). Per BRIEFING gotcha #22 the riscv mtime fallback has epoch 1970 (vault #355 lineage, LEARNINGS:1475) — the server must report DEGRADED rather than pretend. Timer HAL `oneshot/periodic` coarse-tick args and riscv `remaining()` hard-0 (gotcha #20, undisputed) are **not used** by the server.

**INV-T12 — no dynamic allocation on RT paths.** Server tables static (50 + 32); kernel side has no new object type, so no `ResourceTracker` counter is added (PD frames come from `sdf_compose`/`mint_one`, already tracked). Any accidental `new`/`MemPool::alloc` on the tick or RPC path is an audit blocker.

**INV-T13 — ABI stable.** Syscall numbers 80–83, arg shapes and `src/libc/*` stay byte-identical (picolibc untouched); the flip is invisible to userspace callers.

(The scaffold trap at `userspace/timer-srv.c:91-99` — due deadline leaving `timeout==0` — is removed by this reordering, not preserved.)
15. `fire_due()`: for each used slot with `deadline_ns <= now` → emit the op-specific client event (see 16-18) with the INV-T5 token, then non-periodic → `used=0, ++slot_gen`, periodic → `deadline_ns = sat_add(deadline_ns, interval_ns)` (skip if `<= now`, i.e. never burst-catch-up more than one period per wake).
16. `SLEEP_REQUEST`: arm an internal slot keyed by (owner_id, owner_gen, gen); no reply (client is already blocked), fire → `ipc_send(owner_id, MSG_TYPE_REPLY, &rep{token,status=0}, 48)`.
17. `TIMERFD_CREATE/SETTIME/DELETE`: alloc/free slots with `++slot_gen` on free; SETTIME(value=0) disarms AND emits a `STALE_TOKEN` cancel marker for the fd (drain-side cancellation); sync reply via `ipc_send(req.owner_id, MSG_TYPE_REPLY, ...)` like the existing code.
18. `TIMERFD_EXPIRED` delivery: `ipc_send(owner_id, MSG_TYPE_REPLY, &rep{token, count=expiries}, 48)`; `expiries` reset on consume.
19. `CANCEL_OWNERS`: purge every slot matching (owner_id, owner_gen) (existing loop) **and** bump `slot_gen` per purge; bump nothing else. Tombstone drain (piggyback-bound, no new timer): every `fire_due` pass first sweeps dead-owner tombstones (server_epoch check + release), so a dead owner's slots linger at most one wake interval, not until table pressure; `CANCEL_OWNERS` remains the explicit path and `-EAGAIN` at table-full stays fail-closed with the bound documented (`tombstone_drops_total_` counts both).
20. `ANCHOR_PUSH` (from rtc-pd): set `g_anchor_ns = value_ns`, `g_anchor_mono_ns = now_ns()`, clear DEGRADED; reply status 0. On epoch increase from the kernel (flags bit) → purge all slots.
21. After every anchor change (including the degraded→synced transition) the server publishes the anchor to the kernel cell with a one-way `ANCHOR_PUSH` report (op 8, owner_id=0, value_ns=anchor_ns, interval_ns=anchor_mono_ns, flags=DEGRADED/RTC_NEVER) — the kernel then answers REALTIME/`SYS_GETTOD` locally by saturating arithmetic (step 23/28) and no client ever blocks on a wall-clock read.
22. Degraded mode: if no anchor after `kTickOnlyGrace` or `RTC_NEVER` flag, serve REALTIME = `now_ns()` since boot and set DEGRADED in every reply/anchor push; a later anchor push clears it and the next push resyncs (monotone guard applies).

**P4 — kernel proxy flip (timer_srv.cpp + handlers).**
23. `timer_srv.cpp`: `sys_clock_gettime_srv` — MONOTONIC answered from `arch::Timer::ns_monotonic()` directly (hardware fact, INV-T1), REALTIME from the anchor cell; no RPC on either (removes a blocking path from the clock read).
24. `sys_nanosleep_srv`: validate/convert timespec → ns (reuse `timespec_to_ns`), zero → return 0 immediately, else `nsleep_send` (one-way `IPC::send`, server pid+epoch stamped) then `nsleep_wait` (§INV-T8 pattern; filter reply by type `MSG_TYPE_REPLY` + token + `sender_id == server pid`; drop mismatches and re-block; on server death return `-EINTR`). CARRIED LIMITATION (explicit, not an oversight): signal-EINTR for recv-parked sleepers has NO pending-signal probe on this path — the OFF leg probes at `syscall_handlers_posix_time.cpp:250-277`, but under ON the sleeper parks in `IPC::recv` with `sleep_armed==false` so the delivery wake (`proc_svc.cpp:620-621`, alarm tick `:851-853`) cannot reach it, and this step specifies no probe. A signal arriving mid-sleep is therefore NOT delivered as EINTR until the sleep completes or the server dies (server-death EINTR still works). Pinned by QE test `srv_timer::nanosleep_signal_deferred` (signal during sleep → reply arrives first with the full interval elapsed, no hang, no stray wake).
25. `sys_timer_create/settime/gettime/delete` + `sys_timerfd_create/settime`: build `TimerRpc`, `timer_srv_rpc()` (existing validated-reply core), map `status` → return; keep `-EAGAIN` on RPC failure.
26. timerfd read branch (`syscall_handlers_posix_time.cpp:500-630`): ON leg = `timerfd_deliver(index, gen)` — block on `IPC::recv` for a token-matching `TIMERFD_EXPIRED`, return `count`; no `timerfd_waiter_arm/consume` (OFF leg keeps them).
27. `timerfd_close`: ON leg sends `TIMERFD_SETTIME(value=0)` (bounded) before freeing the slot, so the server drops the arm even if the client never does; failure is fail-closed (slot still freed locally, server purges on owner-death tombstone). `timerfd_read_entry` (`syscall_handlers_posix_time.cpp:508+`) gains an ON leg performing the INV-T5 tag-vs-token compare (this is the drop site P6 was missing); the OFF leg is untouched.
28. `sysclock_gettime(REALTIME)` + `SYS_GETTOD` read the anchor cell (saturating add, clamp at `UINT64_MAX`); `PosixTime::boot_latch/clock_realtime_ns` become OFF-leg.

**P5 — RTC driver PD feed (dependency stated, not built).**
29. `driver_pds.hpp`/`userspace/driver_pd.h`: `DRV_OP_RTC_EPOCH=10`, `DRV_OP_RTC_READ=11`; BIND arg1 = timer-srv pid, arg2 = wire version.

## SIL 3 / SAFETY RISKS
- [S1] **Lost wake / permanent client hang.** `nsleep_wait` blocks with no kernel timer by design (INV-T8); a dropped server message or a server death without a wake hangs a client forever, violating §11.3. — Mitigation: death-wake + tombstone path already exercised by #545 M1; handler treats server death as `-EINTR`; test 1 asserts no client stays BLOCKED past the window; add a per-call `g_wait_generation` guard so a recycled TCB never inherits a stale wake.
- [S1] **Stray fire after cancellation** (the `timerfd_multiplex` killer). An event queued before `timer_delete` wakes a slot that is now owned by a recycled (id,gen) or a reused slot index. — Mitigation: INV-T5 token with 5 components, drop-before-wake, `slot_gen` bump on free, epoch purge; tested as the explicit negative (counts per token).
- [S1] **Server time running backwards** under the harness `set_ticks_for_test` rewind (`hal/timer.hpp:104`) → immediate-fire storm, missed deadlines, spin-wake loop. — Mitigation: INV-T4 own monotone latch from `ns_monotonic` only, `ticks()` banned by grep, rewind counted not acted on; saturating deadline arithmetic (#349).
- [S1] **Double-serve** if a runtime fallback stays in a handler (server path *and* in-kernel wheel both arm) — two expiries, double wake, torn timerfd counts. — Mitigation: INV-T7 compile-time single decision point; grep-checked in review that the ON leg has no `sleep_arm`/`timerfd_fire` reachability.
- [S2] **Budget starvation of the server** at SS(1,10,0) if the wake model ever becomes per-tick. — Mitigation: deadline-driven bounded receive (not per-tick pulse, INV-T3); O(50)/O(32) scan; measured WCET posted on the issue; #190 owns donation/overrun.
- [S2] **`kPdRoleCount` truncation** on the appended enumerator (arrays `g_role_frame_phys/g_role_slots/g_role_gens` sized by it). — Mitigation: append last + `kPdRoleCount = TIMER_SRV + 1` + `static_assert`; `sdf_check_bounds` fail-closed on unknown role.
- [S2] **Table-bound mismatch between kernel config and server wire** (kernel says 50, server compiled 32, or vice versa) → fail-open or index overflow in the shared 48 B payload. — Mitigation: `CONFIG_TIMER_SRV_MAX_*` + wire version field + server rejects a mismatched version at BIND (`-EPROTO` shape) rather than guessing.
- [S2] **Restart/snapshot residue**: arms surviving `snapshot_restore` or a PD restart with stale owners/tokens (the #320/#321 class). — Mitigation: INV-T6 epoch bump on both paths + tombstone drain + `snapshot_reset` from `test_isolate`; ResourceTracker delta-0 asserted by every test.
- [S2] **Kernel still reading RTC after the flip** (two wall-time owners → divergent realtime, and the PD loses its reason to exist). — Mitigation: P6 step 28 removes the HAL read from `SYS_GETTOD` and the anchor latch; grep `arch::RTC::read_seconds` must show only `rtc-pd`/HAL-internal callers after the flip (except boot fallback if the owner keeps one — see OPEN QUESTIONS).
- [S3] **`daemon_mgr` name-ternary** (#241 audit S3a) referencing "timer-srv" outside the `#if` and duplicating the TaskDef budget — removed in P2 (also removes the last behavioural difference between OFF/ON boot tables).
- [S3] **docs/specs/timer-srv.md drift** (#241 audit S3b: tombstone-drop and reply-validation wording) — the rewrite in P1 is part of the audited patch, so spec and code land together; the tombstone paragraph is rewritten to drop-newest + `tombstone_drops_total_` counter (not the stale "drops oldest").
- [S3] **`test-history.txt` rows** must carry measured TIME (never estimated) and a `STATUS:` tag for TIMEOUT/STALL runs — an unlabelled row reads as a regression next session.
