## FINDINGS
- [S2] src/kernel/sync/spinlock_order.cpp:78-86 — lock-order enforcement inverted and self-inclusive
  WHY: The check flags a violation iff a held rank is `<=` the new rank, but the normative order is Sched(1)→Queue(2)→Leaf(3) (increasing inward), so legal Sched→Queue nesting (the actual block_sender pattern) warns while illegal Queue→Sched nesting passes silently; worse, the scan runs after the push over all `held.depth` entries, so every ranked take self-flags violations[rank][rank]. This directly contradicts the QE prescription posted on #545 (Queue(2)→Sched(1) must yield violations[2][1]==1; Sched→Queue→Leaf must yield 0) — the implementation produces the exact opposite on both halves.
- [S3] src/kernel/sync/park_lock.cpp:36 — lock_park_allowed omits the NoTicks gate that deny_reason() has
  WHY: The predicate gates a `park_ns /= CONFIG_TICK_HZ` division (park_lock.cpp:115) but, unlike deny_reason() (park_lock.cpp:75-76), never rejects CONFIG_TICK_HZ==0, and nexios_config.h carries no range guard for CONFIG_TICK_HZ — a fail-open divide trap where the sibling function already fails closed. Mirrored in the corrective patch.
- [S3] src/kernel/sync/park_lock.cpp:131-137 — park wait tail exits with IF=0 without restoring entry state
  WHY: The sti/hlt/cli loop breaks after cli(), so non-trap callers (daemon task entries, teardown paths) resume with interrupts disabled; the §4 comment declares safety only for trap-entry (IF=0-owned) contexts, and this exact tail-state shape is a recorded defect class (LEARNINGS sti/hlt/cli tail). Bounded by the next sti and fail-loud via the new watchdog, but unproven for the 11 converted sites outside trap context.
- [S3] src/kernel/arch/hal/irq_guard.hpp:53-59 — IrqGuard depth counter non-atomic and preemptible
  WHY: `++depth[cpu]` executes before cli(), so an ISR-side IrqGuard on the same CPU can interleave the read-modify-write (lost update), and a cross-CPU dtor (task migration while guarded) underflows to UINT64_MAX; both skew only toward permanent park-denial (fail-safe direction, pure spin = status quo), never toward unsafe parking.
- [S3] src/kernel/sync/park_lock.cpp:31 — g_park_denied_reason plain-word write vs atomic readers
  WHY: note_denied() does a relaxed-atomic increment then a plain u64 store while lock_park_denied_reason() reads it plainly — a benign diagnostic race, but the counter it sits next to is atomic; make it atomic or document single-writer.
- [S3] process — no new regression tests in-patch; accepted as tracked QE debt, not a reject
  WHY: Test seams are present (lock_park_count/spin_fallback/violation/fire_count + reset_for_test), QE prescriptions are posted on #545 with stub-first instructions, and the lane split (dev kernel-only, QE testbed) is documented on the issue thread; check-11 evidence rows for the existing suites are present and green (see below).
