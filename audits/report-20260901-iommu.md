## FINDINGS

- [S3] src/kernel/iommu/iommu.cpp:210-327,480-518 — bounded MMIO spin-waits run under a non-IRQ-disabling SpinLock
  WHY: `wait_gsts`/`qi_submit` retry loops (100k/200k MMIO reads) execute while holding `g_lock_`, and `SpinLock::lock()` (spinlock.hpp:43) does not mask interrupts, so a timer-tick preemption into another iommu caller on this uniprocessor target would self-deadlock; the waits are bounded and fail-closed (false on timeout) and this matches the pre-existing iter-1 locking discipline, so it is a hardening note, not a blocker.
- [S3] src/kernel/iommu/iommu.cpp:577-580 — force_present(false) drops only the software live flags, not the hardware GCMD.TE
  WHY: after the last iommu_live test the emulated TE stays set while g_live/g_translation_live are false, so later software-mode mutations issue no QI flush; this is safe only because every live-path map/unmap/destroy already issues a GLOBAL IOTLB flush, leaving the IOTLB empty when the software state drops (walk-through, no stale translations) — fragile but correct invariant, confined to the standalone disk-free class.
- [S3] src/kernel/iommu/iommu.cpp:389-393 — DRHD `include_pci_all` is parsed but unused
  WHY: the passthrough pre-pass unconditionally programs all kernel DMA devices, which is exactly right for the QEMU unit (INCLUDE_PCI_ALL set); on a scope-based DRHD the extra passthrough entries are benign (harmless over-programming), so no safety impact, but the parsed flag should drive the scan scope on real hardware (documented follow-up).
- [S3] src/kernel/arch/x86_64/acpi.cpp:57-63 — acpi_map() returns 0 both for a failed mapping and for a successfully mapped PA-0 page
  WHY: `virt_to_phys_in_pml4 == 0` cannot distinguish "unmapped" from "maps physical frame 0", so an RSDP resident in page 0 would be treated as a mapping failure and the scan fails closed (safe direction — never programs a unit), at worst skipping a legitimate DMAR; no unsafe path.
