## FINDINGS

- [S3] `docs/specs/block-srv.md:66` — spec says "bounded wait (100 ticks,
  `BLK_IRQ_WAIT_TICKS`)" but `userspace/block-srv.c:105` defines
  `BLK_IRQ_WAIT_TICKS 1000UL`. Doc/code factor-of-10 mismatch; code + tests
  agree on 1000, so doc is stale.
- [S3] `userspace/block-srv.c:98` — comment claims "1000 ticks (1 s at
  100 Hz)", but `CONFIG_TICK_HZ` is 1000 (`src/kernel/nexios_config.h:71`),
  so the rate figure is wrong (the 1 s duration is correct at 1000 Hz).
  Comment-only.
- [S3] `src/kernel/irq_delivery.cpp:382-388` vs `:184` — arm programs the
  LEVEL bit unconditionally when the APIC is on, but save/restore is gated
  on `ioapic_unmasked_here` (was-masked). An already-unmasked line keeps
  level programming after release. Theoretical only: the SDF row never
  conveys an unmasked line (init masks 2–15; block vectors 46/47 + virtio
  SPIs are masked at arm), and the GIC path (`:416` set / `:200` restore)
  restores unconditionally — no storm or hang path exists today.
- [S3] `src/kernel/irq_delivery.cpp:411-417` — GIC ICFGR 2-bit field RMW
  runs under the per-slot lock, but one ICFGR word covers 16 INTIDs, so two
  concurrent arms in the same word could clobber each other's trigger
  field. Theoretical only: PD compose is boot-serialized and the row
  carries a single IRQ cap; no concurrent-arm path exists today.

No S1/S2 findings. Safety-critical paths verified sound: slot-reuse
generation guards (recipient/waiter/irq_wait gen); ISR holds the slot lock
for mask-on-delivery; wheel callback sets only the flag with the tick
applying the wake under `scheduler_lock_`; teardown + drain cancel arms;
bounded wait fails closed (full wheel, zero HZ, NOTIFY refused, timeout →
poll fallback); completions never inferred from the IRQ alone (ATA BSY/ERR,
virtio used-ring + status byte, stale-retry bounded at 2 waits); WAIT_ACK
force-mask on release/drain prevents level storms; MSIX never armed in b2;
AHCI_MSI gated on BLOCK_SRV; raw-64-bit mode validation before narrowing.

DECISION: APPROVED
