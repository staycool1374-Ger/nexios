## INVARIANTS & CONCURRENCY BOUNDARIES
- **INV-593-1 (no third death path).** The self leg reuses `terminate_err_from_trap` + `switch_away_from_terminating` — byte-for-byte the aarch64 (`interrupt_controller.cpp:396-402`) and riscv64 (`:291-297`) EL0-fault shape from #523. It must NOT use `terminate_err`: that funnel's self-current scope B calls `switch_to_task` from trap context and resolves the live ISR RSP as save owner (`sys_exit`'s explicit warning, `syscall_handlers_misc.cpp:118-122`).
- **INV-593-2 (residence before wake).** No parent-visible residence may exist before the corpse has left the live tables. Inside the trap funnel the order becomes `dequeue_ready → TERMINATED/exit_code → admin clear → deadline remove → join-note → release_zombie → wake_waiting_parent → reaper poke → publish_task_death`. Rationale: a wake issued while the corpse is still in `all_tasks_` lets the woken parent take `sys_waitpid`'s in-table branch (`:164-189`) and `delete` a TCB whose stack is live on another CPU.
- **INV-593-3 (arm after residence, before trap return).** `switch_away_from_terminating` runs after the funnel returns, so `release_zombie`'s `invalidate_pending_switch_to(task.id)` precedes the new arm (contract at `scheduler_terminate.cpp:231-236`; for a self arm the invalidate is a no-op because the arm targets the successor — `scheduler_lifecycle.cpp:81-88`, `docs/specs/zombie-list.md` §7.3).
- **INV-593-4 (TERMINATED before the arm).** `switch_away_from_terminating` re-enqueues the exiting task when `state == RUNNING` (`scheduler_switch.cpp:1059-1062`); the funnel marks TERMINATED first, so the corpse is never re-queued (INV-2: no TERMINATED task in a ready queue).
- **INV-593-5 (never free a live stack, #197 precedent).** Every free path must spare `is_current_on_any_cpu`: the four drains already do (`scheduler_lifecycle.cpp:175,258,425,484`); `collect_zombie_child` (`:338-401`) and `sys_waitpid`'s in-table free (`:164-189`) do not and are the surfaces a woken/polling parent uses.
- **INV-593-6 (locking).** Funnel contract unchanged: no scheduler lock held on entry (`ENSURE(scheduler_lock_depth_own() == 0)`), `arch::IrqGuard` outer, scope A under `scheduler_lock_`, `publish_task_death` outside it (its own ENSURE), `switch_away_from_terminating` takes the lock itself and publishes the arm after releasing it. Lock order stays global(`scheduler_lock_`) → leaf(`zombie_lock_`), never the reverse.
- **INV-593-7 (cause + code latch order).** `publish_task_death` latches only the first non-zero `death_cause` (`scheduler_terminate.cpp:59-61`), so the funnel must receive the cause and publish it; the inline `publish_task_death` in `sys_kill` is removed (no double latch, no pre-latch that would mask the funnel's cause). `exit_code = -sig` is preserved exactly; cause mapping is `signal_is_fault_class(sig) ? Fault : Kill`, daemon = `Admin` (today's values, unchanged).
- **INV-593-8 (F4 admin latch, #557).** Both funnels clear `admin_parked / admin_wake_pending / admin_stop_requested / admin_wdog_expiry_tick` under the lock and drop the deadline node (`scheduler_terminate.cpp:133-137` and `:260-264`) — the self leg and the daemon path inherit this by using the funnels; no new clearing site is added.
- **INV-593-9 (#221 / #590 interplay).** `reap_orphans` cannot see the corpse after `release_zombie` (it is gone from `all_tasks_`), so the live-parent deferral is untouched; the corpse is reachable only via the zombie residence, where INV-WAIT-5 (`wait_collect_pending_`, set inside the wake at `scheduler_lifecycle.cpp:678`) keeps it unfreeable while its owner lives. A woken BLOCKED parent keeps the parented linkage (`:706-711`), so its rescan resolves through `collect_zombie_child` (the #590 second residence).
- **INV-593-10 (bounded work / RT path).** No allocation, no unbounded loop, no new lock, no widened IRQ-off window, no `new`/`delete` on the death paths; the added predicate is a per-CPU `current` compare loop already used on the same contexts.
- **SMP scope.** Self-kill is `t == current_task()` on this CPU by construction (no cross-CPU self). The daemon path relies on `terminate_err`'s remote-current refusal (`:96-104`): an AP-live daemon is refused with zero mutation, so no live stack is ever freed. SMP test coverage exists only on x86_64 (`tools/test-policy.tsv`: `class|smp|arch_scope|x86_64`).

## SIL 3 / SAFETY RISKS
- [S1] The corpse is marked TERMINATED without an armed switch-away → the trap epilogue iret's/sret's/eret's back into terminated code (rv64: re-fault double-fault park; aarch64/x86: user-mode execution of a dead task). — Mitigation: step 3 publishes the arm via `switch_away_from_terminating` before the syscall handler returns, verified per arch (x86 `isr_stubs.asm:201-213`, aarch64 `syscall_entry.S:79-82`, riscv64 `syscall_entry.S:248-251`); INV-593-4 keeps the corpse out of the ready queue.
- [S1] Double `release_zombie` on the daemon corpse (the funnel now lists it; the existing test teardown releases again → duplicate zombie-list push, later double free). — Mitigation: `task->state != TERMINATED` guard in step 6, plus the mandatory coupled QE edit (step 12). Do not declare `servers_daemon_restart` green before that edit lands.
- [S1] Freeing a live kernel stack while the killer is still on it (a woken or polling parent collecting the corpse in the release→arm window). — Mitigation: INV-593-2 ordering, plus the two collector spares (steps 4-5) so no free path can reach a current corpse.
- [S1] Cause mislatch: publishing before the funnel would freeze `death_cause` at the wrong class (first-writer-wins at `scheduler_terminate.cpp:59-61`). — Mitigation: the self leg no longer publishes at all; the funnel takes the cause and publishes once (step 2e/3).
- [S2] Moving the wake after `release_zombie` changes which residence a woken parent observes (in-table → zombie list). — Mitigation: the #590 second residence already implements the zombie-list collect for exactly this case (`sys_waitpid:141-161`, `collect_zombie_child:338-401`); covered by `process_waitpid`/`process_lifecycle`/`arch_*` runs.
- [S2] x86 post-syscall `reschedule()` on a TERMINATED current (`kernel.cpp:2727-2730`) now runs with an arm already standing. — Mitigation: verify (code read in step 3's review, then the debug gate) that `reschedule`/`switch_to_task` early-return on a standing arm (`scheduler_switch.cpp:955-959` sets `force_apply` and returns; `switch_to_task` requires `save_rsp_to == 0`); no second publish is possible.
- [S2] Daemon refusal leg leaves the entry pointing at a live AP daemon; a restart loop could spin. — Mitigation: the refusal only logs (SCHED+14 already emitted inside `terminate_err`, plus DAEMON+13) and `restart_stale_daemons` is tick-cadenced (100 ticks), so no tight loop; fail-closed beats corrupting an AP-live stack.
- [S3] A polling parent can observe "in flight" (an epilogue-sized window) and take a loud `-1`/`SCHED+23` deny. — Mitigation: accepted under the documented R-1 "deny loudly, never pin" doctrine (`docs/specs/scheduler.md:189-191`); the window is bounded by the epilogue, never by a scheduler decision.
- [S3] Style/complexity: the funnel comment must stay within the 80-column clang-format limit and every new named local must be consumed (the `WakeResult` local uses an explicit `(void)` with the reason, mirroring the `[[nodiscard]]` precedent from #523).
