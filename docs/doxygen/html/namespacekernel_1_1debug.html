Notify helper for the tick deferred-stop park (see header). Lives in the exported scope (not the anonymous TU-local one): the scheduler's tick path calls it across TUs.

Notify helper for the tick deferred-stop park (issue #295): the scheduler's tick path holds scheduler_lock_ so it cannot call debug_park_stop (non-recursive lock) — it parks open-coded and calls here for the notification half. Latches kind 0 (cleanly parked: no trap occurred, so debug_continue plain-resumes and a planted breakpoint refires as a real trap) with the interrupted PC as stop VA, and enqueues a BP-class event (GDB reports any initial stop as T05) + pokes, mirroring the trap path's post-park sequence (lock order scheduler -> stop kept: stop_enqueue takes g_stop_lock, the poke is lock-free). No-op when detached (id 0).

Parameters
pcInterrupted user PC latched as the stop VA.
