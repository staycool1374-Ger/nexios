class  kernel::SchedulerLockGuard
 Checked RAII guard for scheduler_lock_ ONLY (#417). Drop-in replacement for SpinLockGuard<sync::SpinLock> on scheduler_lock_: the blocking constructor takes the lock, the adopt constructor takes ownership of a lock acquired via try_lock(); both mark this CPU's depth slot, the destructor (or early unlock()) clears it. Mark AFTER a successful take and unmark BEFORE release, so an observer never sees a taken-but-unmarked slot (a same-CPU re-take then trips the entry ENSUREs deterministically); another CPU's slot is never touched, so legal cross-CPU contention spins instead of tripping (the #417 fix). Free functions must not outlive the scope (same rule as SpinLockGuard). More...

uint64_t kernel::scheduler_lock_depth [CONFIG_MAX_CPUS]
 Per-CPU scheduler_lock_ take depth (#417; defined in core/global_state.cpp, zero-initialised). Slot [cpu] counts takes of scheduler_lock_ by that CPU not yet released. Single-CPU invariant: 0 outside a take, 1 inside (the lock is non-recursive). SMP: a CPU only ever touches its own slot. NOT part of SchedPerCpuPod snapshots: the depth is transient by construction — test boundaries and quiesce run with the lock released, the same assumption the old global holder_ slot already relied on.
