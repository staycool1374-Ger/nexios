Detailed Description

Order-sensitive path-tracing primitive (issue #347, #362).

Each hot-path step folds its unique bit into a running per-CPU chain; checkpoints and the path end compare the chain against the expected value, so a deviation is detected at validation.

Fold: chain = chain * K + bit (K = golden-ratio odd constant). Unlike the original XOR fold (a^b == b^a), this is ORDER-SENSITIVE — a permutation of distinct steps changes the value — while still detecting a MISSING or DUPLICATED step. Expected values MUST be computed by the same fold via path_expected(...), never hand-derived, so runtime and validator cannot drift.

Rules: observe-only (never gates production control flow — test validators excepted); own-CPU slot only; one multiply+add per step (a few cycles); no allocation; no locks. Preemption between step() and checkpoint() on the same CPU is the caller's contract (functional paths already hold IrqGuard where they step). Cross-CPU handoffs pass checkpoint values by value — never index another CPU's slot.
