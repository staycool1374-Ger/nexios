 		smp.cpp
 AArch64 SMP AP bring-up (issue #351, slice-2). The BSP walks the DTB cpu nodes (slice-1 helpers), publishes the AP entry cells, then wakes each secondary with PSCI_CPU_ON (SMC/HVC conduit from the DTB psci node) as primary or the spin-table cpu-release-addr hold-loop as fallback. Woken APs run ap_main() (per-CPU + GIC + timer init) and idle on wfi with timer ticks live (Phase C scheduling lands in slice-4/5). Runs once at boot under interrupt guard; any failure parks with zero APs or panics naming the MPIDR — never half-woken. Single-CPU topologies (DTB cpu count <= 1) are a silent no-op.
 		smp.hpp
 AArch64 SMP AP bring-up (issue #351, slice-2). The BSP discovers CPUs from the DTB (slice-1 helpers), then wakes each secondary with PSCI_CPU_ON (SMC/HVC conduit from the psci node) as primary or the spin-table cpu-release-addr hold-loop as fallback. Woken APs run ap_main() (per-CPU + GIC init) and idle with timer ticks (Phase C scheduling lands in slice-4/5). Single-CPU runs are a silent no-op. AArch64-only.
 		smp_shootdown.cpp
 AArch64 strong cross-CPU TLB-shootdown hook (issue #389). Overrides the weak VMM::smp_tlb_shootdown_hook no-op: sends one SGI SMP_SHOOTDOWN_SGI per up CPU (Aff0 via ap_aff0, S4 interface arch::send_shootdown_ipi). Purge-on-receipt: the SGI carries no payload, so the target applies a self-purge via the existing tlb_flush_all primitive (tlbi vmalle1) in the SGI-10 handler registered by kernel.cpp — no shared VA queue (a per-VA queue would be new cross-CPU shared state, i.e. #386 surface). IS form (VMALLE1IS) is explicitly NOT required: the handler runs on the target, so a self-purge suffices.
