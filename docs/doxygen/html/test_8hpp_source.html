180// ============================================================================
181// DRIVEN-TEST COOKBOOK — reference skeletons (documentation only, never called)
182//
183// Every kernel test must DRIVE the system to a state through real dispatch,
184// then TRIGGER a real event (timer tick / ISR / syscall / real terminate),
185// then VERIFY the reaction. These skeletons capture the exact patterns that
186// fix the observed parent/child and blocked-sender HANG classes. A test that
187// copies them is deterministic, leak-free, and cannot wedge the scheduler.
188//
189// MANDATORY RULES (each one stopped a real hang):
190// 1. CREATE both TCBs first and set every field/queue BEFORE registering
191// either task with the scheduler. The timer ISR fires between arbitrary
192// instructions, so a task added early can be dispatched (and terminate)
193// before the harness finishes arranging the scenario.
194// 2. REGISTER multiple cooperating tasks under one `arch::IrqGuard` so no
195// timer tick can split the registration. The higher-priority task that
196// must BLOCK runs first; the lower-priority peer runs after it blocks.
197// 3. WAIT on observed task state (`task->state == TaskState::BLOCKED`) with
198// `asm volatile("pause")`. Never assume ordering.
199// 4. RECLAIM self-terminated tasks via `Scheduler::drain_zombie_list()`.
200// `Scheduler::terminate()` only marks a task TERMINATED and moves it to
201// the zombie list — it does NOT free the TCB. Never follow it with
202// `remove_task()+cleanup()+delete` (double-free on a poisoned block).
203// 5. CLEANUP BEFORE ASSERT: drain zombies / terminate stray live peers
204// BEFORE `JARVIS_ASSERT*`. Assertions `return` on failure, so asserting
205// before cleanup leaks the TCB (observed as `PMM +17, Tasks +1`) or
206// leaves a live task that hangs the whole class.
207// 6. External termination of a task blocked in `Semaphore::wait()` is SAFE
208// since v0.3.12: `TaskControlBlock::cleanup()` unlinks the task from the
209// semaphore's waiter list via the `waiting_on_semaphore` back-pointer
210// (v0.3.9 teardown gap closed). Verify teardown with
211// `semaphore_waiter_teardown_on_terminate` — do not re-add the old
212// workaround (avoiding the scenario instead of testing it).
213// ============================================================================
