Detailed Description

Dispatch-path step registry (issue #347 Slice B) + teardown segment (issue #324 Tick 13).

One traced segment per dispatch phase; segments are independent scratch records (tests own the reset discipline — production never resets and never validates). Early-return legs (EDF detour, idle fallback, skipped-current drop, bad-frame dispatch guard, self-switch no-ops) are explicit terminal paths: they record nothing and validate against nothing. switch_to_task() is file-static, so its apply segment is exercised by the suite (observe-only) and covered by inspection; reschedule()/next_task() segments are driven by tests.

The teardown segment traces the scheduler side of task death (terminate_err → release_zombie → drain-pop commit); the TCB side (all 14 cleanup blocks) is traced by task_path.hpp into the same per-CPU slot, so one chain covers death end to end. Terminal paths (reap arm, deferred destroy, pinned spare, OOM legs) record the documented prefix and validate against the prefix expected value.

The registry lives in its own header (not function-scoped) so the #323 split moves it together with the dispatch code, zero renumbering.
