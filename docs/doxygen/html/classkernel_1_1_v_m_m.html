 Converge a child PML4's kernel half (entries 256..511) toward src_pml4 (issue #96, kernel-half merge). Recursive top-down walk (PML4→PDPT→PD→PT): wherever the child lacks an entry present in the source, the entry is copied by value (link semantics — lower tables stay shared, never duplicated); entries already present are left untouched (idempotent); huge/leaf entries are copied by value. Performs ZERO allocations, so it cannot OOM by construction; the bool preserves the failure contract for future allocating revisions (callers must destroy the child table on false). No locking: single-threaded, runs before the first CR3 switch to the child (same window MP-7 uses).

Detailed Description

Virtual memory manager — maps virtual to physical pages.

Note
Naming (issue #363): pml4 names the page-table ROOT cross-arch (x86_64 PML4, aarch64 L0, riscv64 Sv39 L0) — not the Intel format.
Page-walk depth is fixed per architecture (4 levels for x86_64/aarch64, 3 levels for riscv64 Sv39). Huge-page split (512 iterations) occurs at most once per 2 MB region. Both walks are bounded, meeting hard-RT WCET requirements for map_page / map_page_in_pml4.
Supports user/kernel page flags, TLB flush after each mapping.

◆ deep_copy_user_pages()

bool kernel::VMM::deep_copy_user_pages ( uint64_t src_pml4,
uint64_t dst_pml4 )
static

Frees all user-space pages and page tables from a user PML4. Used during exec() to clean up the old address space. Skips kernel-owned pages (PMM::is_user_page owner-bit check) — v0.4.0 MP-7: no task shares another's user entries, so this is always the full teardown of a private address space. Defensive block sites (1 GiB / 2 MiB) validate level alignment via decode_block_base and skip misaligned entries, never freeing them: no in-tree producer creates user huge/block leaves (#365).

Deep-copy user-space page tables from src_pml4 to dst_pml4. Allocates new PDPT/PD/PT pages and copies data page content. dst_pml4 must already have kernel entries populated. Worst-case: PML4_USER_COUNT (256) × 512 × 512 × 512 leaf visits, each doing a 4 KiB memcpy. Yields every 64 leaf entries.

Parameters
pml4_physPhysical address of the user PML4.

Deep-copy user-space page tables from src_pml4 to dst_pml4. Allocates new PDPT/PD/PT pages and copies data page content.

Parameters
src_pml4Physical address of source PML4.
dst_pml4Physical address of destination PML4 (must already have kernel entries populated).
Returns
true on success, false on OOM or on a user-OWNED huge/block entry (issue #325-E: by-value copy would alias one writable page parent/child — fail closed instead; issue #387: kernel-owned blocks reachable in the user index range — riscv64 L0[0] low-half MMIO/identity from clone_kernel_pml4 — are inherited BY VALUE, never a fork failure, U=0 kept). Partial state may remain on false, but every installed TABLE page is USER-owned and every inherited BLOCK is kernel-owned U=0 (skipped by every free_user_pages block site on all arches), so the caller MUST destroy the child (TaskControlBlock::destroy → cleanup → free_user_pages reclaims all partials — task.cpp documents this invariant). Leaf flags (USER/write/dirty/accessed/NX) copy verbatim; non-RAM frames are skipped (child leaf stays unmapped).
Note
Concurrency/caller contract (issue #366): Lock: none (VMM-internal; TaskControlBlock::clone runs without IrqGuard here). Context: kernel-only (fork path). SMP: source and destination are not live on any CPU (pre-publish window); the caller MUST destroy the child on false (see above).
Returns
true on success, false on OOM.

◆ merge_kernel_half()

bool kernel::VMM::merge_kernel_half ( uint64_t src_pml4,
uint64_t dst_pml4 )
staticnodiscard

Converge a child PML4's kernel half (entries 256..511) toward src_pml4 (issue #96, kernel-half merge). Recursive top-down walk (PML4→PDPT→PD→PT): wherever the child lacks an entry present in the source, the entry is copied by value (link semantics — lower tables stay shared, never duplicated); entries already present are left untouched (idempotent); huge/leaf entries are copied by value. Performs ZERO allocations, so it cannot OOM by construction; the bool preserves the failure contract for future allocating revisions (callers must destroy the child table on false). No locking: single-threaded, runs before the first CR3 switch to the child (same window MP-7 uses).

Note
Shared-table contract (issue #325-F): shared lower tables are KERNEL-owned (allocated without user_alloc), so child teardown (free_user_pages) always skips them — a child can never free a table the live kernel half still references. Late kernel mappings and huge-page splits rewrite shared entries in place and are visible to all sharers; splits allocate fresh tables, never mutate shared ones in a way that orphans sharers.
No copy-on-write exists in this kernel (answer to "when does COW take place": never): fork deep-copies user pages (deep_copy_user_pages) and shares only kernel-half tables, which are never written through user paths.
TLB locality contract (issue #325-F): every VMM map/unmap site flushes the VA locally (issue #225 discipline). Local-only sufficiency rests on: (a) user tasks execute on CPU0 exclusively (scheduler CPU0 pin, #25 C1), so user TLB entries live on one CPU; (b) CR3 switches flush untagged entries (exec path) and pcid_free purges on PCID release; (c) freed tables are never reactivated (teardown destroys the PML4; exec switches before freeing). Cross-CPU invalidation beyond this is owned by the selective/lazy shootdown mechanisms (#157/#158).
Free-vs-use ordering (issue #325-F): page-table teardown runs only for dead tasks (cleanup/reap paths) which cannot run on another CPU (CPU0 pin + dead-state filter), after the pager/cap/ELF drains (see TaskControlBlock::cleanup ordering) — a live mapping is never freed under a user.
Parameters
src_pml4Physical address of the source (canonical) PML4.
dst_pml4Physical address of the child PML4 to converge.
Returns
true on success, false on invalid arguments (null or identical roots — never on allocation failure).
Note
Concurrency/caller contract (issue #366): Lock: none. Context: kernel-only. SMP: single-threaded pre-CR3-switch window (same window MP-7 uses) — see the No-locking note above; the canonical example for this triple.
